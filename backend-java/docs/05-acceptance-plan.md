## 1. 通过标准

相同模板、字段值、业务作用域与初始数据库状态，分别运行原后台和Java后台。逐项比较HTTP状态、业务错误码、规范化响应、数据库最终状态、飞书记录最终状态与文件内容。仅健康检查、编译成功或模拟接口成功不能判定正式可用。

两个服务使用独立数据库或独立schema，飞书使用独立测试表/记录，测试应用回调指向测试域名。不得把正式请求直接重放到会上传附件、写模板或更新记录的接口。原后台继续提供正式服务。

## 3. 具体样本与比较规则

文件样本至少包含：单页中文文本、多页分页、动态字段、长文本换行、图片、复杂表格、空字段、PDF与PNG。使用当前正式业务的脱敏模板，而非只使用人工构造的简单模板。PNG只输出第一页的限制必须两边一致。PDF可能包含时间戳、对象顺序或压缩差异，不要求文件哈希相同；比较逐页尺寸、文字及同一工具/分辨率生成的图片。任何像素容差先记录基线，再由人工确认，不能直接忽略全部差异。

接口比较只排除明确动态字段：traceId、OAuth随机state/PKCE、签名时间和随机ID。排除的是随机值本身，仍验证类型、存在性、关联关系、有效期及签名可验证。不得忽略业务ID、artifactKey、taskKey、错误码、状态、pageCount、作用域与字段值。OAuth重放使用各自新建的state/session，不能复用另一后台的单次凭据。

任务样本包括：新任务、重复提交、failed后重试、成功后重复提交、无效签名、凭证过期、字段不存在/类型错误、20MiB边界、上传失败、回写失败、限流、渲染超时、进程重启。恢复测试必须在隔离环境主动杀进程并查询数据库及测试记录，单元测试不能替代。

每个案例记录：案例编号、输入夹具、原后台版本、Java JAR哈希、初始状态、两边结果、差异、结论、日志与产物位置。发现差异先修复，再重跑关联案例；接口/协议变更需重跑完整基线。

## 4. 测试环境准备

1. 本机配置`DUOWEI_TEST_POSTGRES_URL`、`DUOWEI_TEST_POSTGRES_USERNAME`、`DUOWEI_TEST_POSTGRES_PASSWORD`，指向允许创建随机schema的专用库。集成测试仅删除自己创建的schema，不自动使用应用数据库配置。
2. 准备原后台测试实例和Java测试实例的HTTPS地址。Java独立测试应用配置参考根目录`.env.example`，不要提交密钥。原平台注入与代理前缀需显式适配。
3. 准备飞书测试应用、测试多维表格、可编辑与只读用户；配置回调域名和已有所需权限，保持业务配置一致。不自行扩大正式应用权限。
4. 导出脱敏业务模板及字段样本；记录两边浏览器、字体、时区、语言与页面尺寸。
5. 从仓库根执行`node backend-java/scripts/check-acceptance-env.mjs`，只检查本机工具及配置是否存在，不访问数据库、飞书或打印密钥。此检查不等于连接测试。
