<title>ADR-0024 — 关联明细完整读取与原生表格分页</title>

- 状态：accepted / implemented locally（Goal v16；正式 E2E 开放）
- 日期：2026-10-10
- 关联规格：`SPEC-LINK-01/02/03`、`SPEC-BATCH-03`

# 背景

现有代码已经识别飞书关联/双向关联字段类型 18/21，可读取目标表首个视图的字段顺序，并把前五列明细作为数组绑定到 `vue-print-designer` 原生 table。当前缺口是：重复 ID 没有显式拒绝，core 包装可能吞掉可重试超时语义，长明细跨页、续页表头、批量主记录边界还没有真实引擎证据。正式测试 Base 又没有关联字段，不能通过修改业务表来凑验收数据。

# 决策

1. 关联 ID 以 SDK 刷新后的 link 值为事实源，严格保留原顺序；非空字符串以外的 ID 以及重复 ID 均拒绝，不静默过滤或去重。
2. 目标表首个可用视图决定明细列顺序，MVP 最多取前五列，避免无界列宽压缩。没有可用视图时拒绝整个候选。
3. 普通明细单元不可读时显示字段级降级文本并保留该行；记录不存在、读取不完整或关联结构无效时拒绝整个候选。
4. `BitableReadTimeoutError` 保持可识别的超时语义，不能被改写为普通关联记录错误；其他记录级异常补充具体关联 ID。
5. 关联明细只使用一条数据链：`LinkCellValue → ExpandedLinkedRecords → PrintJob → table variable`。预览、编辑、打印与 PDF 不另建明细模型。
6. 长明细只使用 `vue-print-designer@1.7.39` 的原生 table、`autoPaginate` 和 `showHeader`；不自制表格分页器或打印画布。
7. 默认批量为每条主记录隔离数组变量并保持文档边界；保存只回收公共模板。连续排版继续拒绝 table/关联明细，标签排版不承载主从单据。

# 验收

- 单元/契约测试覆盖类型 18/21、首视图前五列、原顺序、空值、无效/重复 ID、无视图、字段降级、缺失记录和超时穿透。
- 默认批量两条主记录各自绑定可区分的明细数组，回收后无业务值、记录 ID 或投影元数据。
- 真实设计器夹具覆盖 0 行、1 行、跨至少三页长明细和两条主记录；每页表头一致，每个唯一编号恰好一次，HTML 与 PDF 均成功。
- 正式 E2E 只在获得独立受控关联样本后执行；本地证据不得冒充正式 Base 通过。

# 边界

本 ADR 不修改正式 Base 的表、字段或记录，不新增权限，不改管理后台，不上传发布。若真实 SDK 契约与当前假设不一致，先更新 SPEC 和失败测试，再修改实现。
