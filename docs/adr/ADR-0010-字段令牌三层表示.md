<title>ADR-0010 — 字段令牌采用持久、编辑、渲染三层表示</title>

- 状态：accepted（正式双字段编辑、保存、跨记录解析与 PDF 已通过）
- 日期：2026-09-26
- 关联：ADR-0009、BUG-0004、BUG-0006、SPEC-SRC-04/05/06/07

# 背景

Goal v2 为支持同一文本组件多个字段，引入稳定 Token `@__duowei_field_<fieldId>` 并在输出前临时解析。正式 Base 证明该方案只完成了持久绑定和输出纯函数，没有完成编辑体验：设计器把内部 Token 当普通文字，编辑和失焦都直接暴露技术标识。

仅把 Token 改为 `@字段名` 会重新引入字段改名、同名字段和跨表误绑；仅在打印前解析又无法让编辑画布反映当前记录。需要明确区分用户表示与持久绑定。

# 决策

1. 字段引用采用三层表示：持久层使用稳定字段/系统 ID；内容编辑层显示 `@当前字段名` 或 `@系统项名称`；失焦、预览和输出层显示当前 PrintJob 的实际值。
2. 友好字段名只是当前标签，不是绑定键。字段改名后标签随当前元数据更新，持久 ID 不变；同名字段不得只靠名称解析。
3. 进入内容编辑时，从稳定模板和当前 DataSourceCatalog 生成友好标签；结束编辑前把标签选择映射回稳定 ID，再生成当前记录的失焦表示。保存始终读取稳定模板，不读取已解析画布文本。
4. 多字段内容必须保留静态文字、字段顺序、分隔符和系统项；数组/关联字段继续使用表格组件专用配置，不强行转为普通文本。
5. 字段删除、无权或旧模板歧义产生显式失效节点。失效节点保留原 ID 以便恢复，不猜测新字段，也不向用户显示原始命名空间字符串。
6. DataSourceTokenCodec 负责可逆转换和错误模型；DesignerAdapter 负责真实引擎的选中、编辑、粘贴、失焦和模板往返；WorkspaceShell 只编排状态。不得在多个 UI 组件中各自维护转换规则。
7. 优先使用公开 API。若锁定版引擎没有足够事件/API，只允许在 DesignerAdapter 的单一版本固定契约内访问 shadow DOM，并补真实安装包契约测试和升级退出条件；不重做画布。
8. 现有 Goal v2 稳定 Token 模板原样兼容。实现不得要求迁移或覆盖用户模板；首次有效保存可补充非业务字段标签元数据，但稳定 ID 仍是唯一绑定事实源。

# 未选择方案

- 直接向用户展示内部 Token：实现简单，但不可理解，正式环境已证明不满足产品要求。
- 把 `@字段名` 直接作为持久绑定：字段改名、同名字段和跨表模板会误绑。
- 失焦时把实际值写回模板：切换记录后无法更新，并可能把业务数据持久化。
- 只在打印/PDF 前解析：不能完成编辑画布和保存重开的用户闭环。
- 自制文本画布替代引擎：违反真实 `vue-print-designer` 边界，形成第二套编辑事实源。

# 后果

实现复杂度从字符串替换提升为受控编辑生命周期，但换来稳定绑定、可理解编辑和当前值预览的一致性。测试必须覆盖可逆转换、异常退出、改名/删除/同名字段、多 Token 和真实引擎事件。若锁定引擎不能稳定提供选择与编辑边界，应停止在技术调查门，不用 DOM 事件注入或独立输入框冒充完成。

# 转为 accepted 的条件

SPEC-SRC-06/07 的单元、锁定引擎契约和正式 Base E2E 全部通过；现有多模板、草稿保护、组件拖拽、打印和 PDF 不回归；模板快照证明只保存稳定绑定、不保存当前记录值。

2026-09-26 复核：实现和 94/94 本地测试已通过，灰度包 `1.0.17/1.0.13` 已在正式 Base 加载；现有契约包含引擎源码断言及适配器替身往返，尚缺真实浏览器中的文本操作和打印/PDF 证据，因此状态仍为 proposed。

补充决策：同名标签的新增引用必须优先使用本次粘贴发生的文本位置识别稳定 ID，剩余旧引用才按原顺序保留。若位置与最终内容不一致或不足以确定绑定，则报告歧义并阻止保存，不按“旧引用在前、新引用在后”的数量规则猜测。对应 Red→Green 回归随 `1.0.18/1.0.14` 灰度；真实 E2E 仍是转 accepted 的门槛。

2026-10-06 正式 E2E 已满足接受门：同一文本组件以 `@客户名称 @数量` 完成友好编辑、失焦真实值、保存重开、再次编辑、`PO-0001→PO-0002` 重新解析和实际 A4 PDF；模板保存回执明确未写入当前记录值，页面未出现内部 Token。字段真实改名、删除/无权/歧义仍需受控样本，但它们是已接受决策的边界验证，不再阻止 ADR 转为 accepted。
