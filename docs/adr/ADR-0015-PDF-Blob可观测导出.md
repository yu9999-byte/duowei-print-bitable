# ADR-0015 PDF 导出先取得并校验 Blob

- 日期：2026-09-30
- 状态：accepted（已灰度；四组正式批量 PDF 已落盘并完成逐页验收；系统打印物理页数待验）
- 关联：`SPEC-OUT-02/03`、`SPEC-BATCH-02`、`SPEC-LABEL-02`、`SPEC-CONT-02`、PHASE-04

## 背景

`vue-print-designer@1.7.39` 的 `export({type:'pdf'})` 和 `exportBatchPdf()` 会在组件内部直接触发浏览器下载。产品只能知道调用 Promise 已结束，无法知道实际生成的文件是否为空、包含几页或有多大。正式连续排版验收因此只能显示“已发起 PDF 导出”，Codex 内置浏览器也无法取得跨域插件 iframe 内的下载文件，不能把入口成功当作文件通过。

## 决策

1. 单条、标签和连续排版统一调用真实引擎 `export({type:'pdfBlob'})`；默认批量调用 `getBatchPdfBlob()`。不自行绘制 PDF，不替换引擎。
2. 适配层在下载前读取 Blob：要求内容非空、以 `%PDF-` 开头，并至少包含一个 `/Type /Page` 页面对象。校验失败时不触发下载，界面显示明确错误。
3. 校验通过后，由产品创建一次临时 `blob:` 下载链接，设置稳定文件名并提交浏览器下载；60 秒后回收 Object URL。
4. 输出用例返回 `{filename, bytes, pages}`。工作台显示“PDF 已生成：N 页，X KB；已提交浏览器下载”，不再把“已发起”表述为已生成。
5. 页数和纸张尺寸识别只针对锁定的 `vue-print-designer@1.7.39` / jsPDF 1.4 输出契约，不是通用 PDF 解析器。该输出的 `/MediaBox` 左下角为 `(0,0)`，适配层读取右上角坐标作为 pt 宽高；每页解析完整才回传 `pageSizes`。升级引擎后若使用非零原点、对象流、继承式页面尺寸或其他结构，必须先更新契约测试和解析方案，不能静默伪造尺寸。

## 后果

- 用户能区分“真实 PDF 已生成”和“只发起了导出调用”。
- 默认、标签、连续和单条共用相同成功/失败语义，减少输出分支差异。
- 浏览器仍可能因策略阻止文件落盘；产品能证明 Blob 结构已生成并明确“已提交浏览器下载”，但不会声称用户已保存文件。
- 四组批量 PDF 的视觉内容已有正式产物证据；单条 PDF、系统打印物理页数和打印机驱动仍需独立验收，本决策不关闭 `BUG-0002`。
