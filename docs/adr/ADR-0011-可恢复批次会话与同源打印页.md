<title>ADR-0011 — 可恢复批次会话与同源打印页</title>

- 状态：accepted for Goal v5
- 日期：2026-09-26
- 关联：`SPEC-BATCH-01/02/04/05/06/07`、PHASE-04、BUG-0002

# 上下文

旧实现把“批量选择”作为孤立按钮，并用 `printJob.documents.length > 1` 隐式判断模式。打开官方选择器前即清空当前任务、模板和预览，取消会留下空工作区；批量屏内预览调用 `getBatchPdfBlob`，浏览器打印则逐条调用 `getPreviewHtml`，两套渲染来源无法保证页数与内容一致。

排版打印官方知识库与录屏证明：记录详情插件先选择最多 50 条记录，确认后进入明确批量状态；批量预览分默认、连续、标签三种模式，最终调用浏览器打印。竞品材料没有证明取消恢复、输出顺序或预览/打印同源，因此这些由本项目规格自行保证。

# 决策

1. 新增纯业务模型 `BatchPrintSession`，明确 `single-ready` 与 `batch-ready`，集中 50 条上限、当前宿主记录、已提交 ID 和摘要。
2. 打开选择器只创建候选。取消、空选、超限或读取失败不修改 committed session；完整 PrintJob 和预览页面准备成功后才提交新批次。
3. 新增 `RenderedPrintJob`/`renderPrintJobPages`。屏内预览和浏览器打印复用同一有序页面对象；打印阶段不得再次调用设计器渲染。
4. PDF 继续使用锁定引擎的单个/批量导出 API，但必须与 canonical pages 对照记录顺序、字段值和页边界。
5. Goal v5 只实现默认排版。连续和标签模式另行调查模板尺寸、纸张高度、横向排列及浏览器分页，不在引擎外制作替代画布。
6. `BitableGateway` 对主记录采用最多 4 个并发 worker，结果按选中索引写入。任一核心读取失败即停止派发未开始的记录，等待在途读取收尾再拒绝候选；字段级可降级读取仍遵循 SPEC-DATA-02。4 是未取得正式限流数据前的保守候选，不声称为 SDK 最优值。
7. 摘要字段以 SDK `isPrimary` 元数据为准，不能假定字段列表第一项就是主字段；仅在元数据缺失的旧任务中回退首个非关联字段。主字段值为空时以记录 ID 明示，避免摘要空白。
8. canonical pages 从引擎 HTML 解析实际分页数量；空页面容器是候选失败，不可用 `Math.max(1, 0)` 伪造一页并提交批次。
9. 输出组合阶段把引擎 HTML 的顶层非资源节点转换为应用拥有的显式页面容器；`style/link/script` 保持资源节点但不计页，打印 CSS 不再依赖引擎内部嵌套 DOM。

# 后果

- UI 不再以文档数量猜测模式，取消选择不会破坏当前工作区。
- 同源页面减少“屏内一页、打印两页”的双渲染差异，但正式浏览器的 `@page`、边距和缩放仍须 E2E 验证。
- 锁定版引擎预览 HTML 为固定尺寸页面并在页面之间保留 20px 间距，插件打印 CSS 会移除该间距。同一缓存只能证明内容来源一致，不能替代实际 Edge/Chrome 页数证据；BUG-0002 不因本决策自动关闭。
- 显式页面容器隔离了引擎内部布局节点，避免内部 `div` 被浏览器误当成分页边界；该结构修复通过本地契约和真实引擎隔离测试，但不替代系统打印对话框物理页数验收。
- 页面缓存必须在模板、记录或上下文变化时失效；业务值只存在 PrintJob/运行态，不写入 BatchPrintSession 或模板。
- 连续/标签能力不会被假按钮或隐藏分支提前承诺。
- 50 条不会同时启动 50 个主记录读取，但每条记录内部字段仍并发读取；真实限流、耗时和内存须由正式 Base 的 E2E-BATCH-03 测量，再决定是否调整 worker 数或字段读取策略。

# 复议条件

若正式 SDK 证明记录选择返回顺序不稳定，新增排序 ADR；若锁定引擎 HTML 无法在 iframe 和当前文档打印中复用，停止 Goal v5 扩展并报告限制，不回退为逐条打印弹窗。
