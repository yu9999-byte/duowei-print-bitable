- 关联：`FR-OUT-01/02/03`、`SPEC-OUT-01/02/03`、BUG-0002、ADR-0006、ADR-0011、ADR-0015

# 背景

正式 Edge 曾出现“产品预览一页、浏览器原生打印两页，第二页只有浅灰残片”。现有实现已经把引擎顶层纸张转换为显式页面容器，但 `vue-print-designer@1.7.39` 的真实输出仍在纸张根节点保留画布阴影，且应用的 `html/body/root`、页面宽高、溢出和分页规则分散在全局 CSS、运行时字符串和浏览器测试中。模板纸张恰好填满 `@page` 时，阴影、视觉溢出或浏览器像素取整仍可能形成额外分页碎片。

# 决策

1. `RenderedPrintJob` 继续是屏内预览和浏览器打印的唯一 canonical page 集；不修改、不替换 `vue-print-designer`。
2. `DesignerAdapter.composeBrowserPrintDocument()` 成为浏览器打印文档规则的唯一生产实现。当前文档打印、真实引擎浏览器测试都复用它，不再各写一套打印 CSS。
3. `@page` 直接使用模板 `canvasWidth/canvasHeight`；无效或非正尺寸明确失败。
4. 打印媒体下显式归零 `html/body` 的 margin、padding 和最小宽度；打印根固定为纸张宽度且只承担全部页面的纵向排列。
5. 每个 `data-duowei-print-page` 固定为模板纸张宽高，`box-sizing:border-box`，`overflow:hidden`，`break-inside:avoid-page`，非末页强制分页，末页明确 `break-after:auto`。
6. 只清除页面容器及其第一层引擎纸张根节点的 `box-shadow/filter/outline`，不清除模板内部组件的业务样式；第一层纸张根节点固定为页面 100% 宽高并裁掉设计器专用视觉溢出。
7. PDF 仍由锁定引擎原生 API 生成；新增无下载副作用的 `getPrintJobPdfBlob()` 供一致性测试复用，产品下载继续先校验 Blob 再提交浏览器。

# 后果

- 设计器画布的阴影和预览装饰不再参与浏览器分页，页面边界由产品显式拥有。
- 单条、默认批量、连续长纸和标签跨页共用同一打印规则；测试不会因复制 CSS 而与生产漂移。
- 浏览器 PDF 与引擎 PDF 对 A4 的 pt 数值可能存在小于 1 pt 的 Chromium/jsPDF 换算差异，但页面语义、画布尺寸来源、页数和内容边界一致；不得把打印机驱动主动缩放或改纸型归因于应用。
- 本地 Edge/Chrome 无界面打印可以证明 Chromium 排版引擎结果，但不能读取飞书正式容器中的系统打印预览 UI。正式 Base 的屏内预览与 PDF 已通过；Codex 隔离浏览器仍不能读取系统原生打印框的物理页数，因此 BUG-0002 保持开放。

# 复议条件

若正式飞书容器仍产生额外页面，必须采集该版本真实打印 DOM、计算样式、浏览器版本和系统打印预览页数，先证明差异发生在应用页盒、宿主样式还是系统驱动；不得继续叠加猜测性 CSS，也不得回退为独立 Demo、自制打印引擎或逐条弹窗。
