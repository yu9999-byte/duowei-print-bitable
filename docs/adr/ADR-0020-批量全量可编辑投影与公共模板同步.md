<title>ADR-0020 — 批量全量可编辑投影与公共模板同步</title>

- 状态：accepted（Goal v13）
- 日期：2026-10-09
- 取代：ADR-0019 的“示例记录 i/N、上一条/下一条、只显示一个模板单元”决策
- 保留：ADR-0019 的设计器完整高度链和内部单一滚动所有权

# 背景

Goal v12 用“示例记录 1/N”解释一批记录共用一份模板，但它仍让真实设计器一次只显示一条记录。用户无法像批量预览一样从第一条连续滚动到最后一条，也会把“编辑公共模板”误解为“只能编辑当前记录”。竞品“排版打印”的公开说明与演示表达的是一份模板投影到全部已选记录：批量结果完整展开，用户在同一个工作区滚动查看和编辑；没有记录级独立模板。

# 决策

1. 批量预览与批量编辑都展示全部已选记录；不再提供示例索引、上一条/下一条或记录级模板。
2. 批量编辑仍只有一份公共模板定义。进入编辑时由 `BatchEditProjection` 生成仅存在于内存的全量画布：
   - 默认模式按“公共模板页 × 已选记录”展开全部页面；
   - 连续模式把公共模板按记录顺序展开为一张完整长画布；
   - 标签模式把每条记录展开到最终标签网格并按容量续页。
3. 每个投影实例继续读取对应多维表格记录的真实字段值。投影使用内部元素映射和临时变量隔离各记录值，用户界面不得显示内部标识。
4. 用户修改任意一个实例后，系统在一次已提交的设计器交互结束时把该实例回收为新的公共模板，再重新投影到全部实例；因此布局、静态文字、组件样式和页面设置统一同步。若同一同步周期检测到多个实例存在不同修改，明确拒绝并要求撤销冲突，不静默选择覆盖。
5. 保存前必须完成一次同步和回收。模板仓库只接收一份公共模板，不得写入业务字段值、记录 ID、批量实例副本或 `__duoweiBatch*` 投影元数据。
6. 批量编辑继续隐藏模板目录，左侧只显示唯一数据源/组件操作区，右侧由真实 `vue-print-designer` 持有画布滚动。返回预览恢复同一模板、同一记录顺序和同一布局。
7. 输出仍由公共模板和 `PrintJob` 生成 canonical pages；编辑投影不是打印/PDF 的第二套事实源。
8. 锁定版设计器的文本编辑发生在 Shadow DOM 内。批量状态下，文本 `focusout` 必须直接进入“回收公共模板并全量重投影”的路径；初始绑定先归一化引擎从 Token 内容推断出的变量，不能把该运行时推断误判为多实例冲突。

# 后果

- 用户在默认、连续、标签三种模式中都能从第一条滚动到最后一条并直接编辑，不再逐条切换。
- 工作台、设计器适配层和仓库分别只拥有会话、投影、公共模板，职责不重复。
- 投影同步会重载同一份全量画布；输入过程中只标记草稿，失焦、变更、拖放或指针操作提交后再同步，避免每个字符都重载设计器。
- Goal v13 已在用户单独授权后以小组件 `1.0.42` / 应用 `1.0.39` 仅向 `F225904757` 灰度发布；权限变更“暂无”、未全量发布。正式 Base 已加载 `assets/main.10b67076.js` 并通过三种布局的全量编辑验收。
