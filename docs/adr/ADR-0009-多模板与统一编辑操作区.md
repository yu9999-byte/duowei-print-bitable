<title>ADR-0009 — 多模板与统一编辑操作区</title>

- 状态：accepted（产品与架构决策；实现及正式环境验收待完成）
- 日期：2026-09-24
- 取代：ADR-0007 的单活动模板决定、ADR-0008 的模板目录编辑入口和只读编辑面板、ADR-0005 的字段名变量 ID；其他边界仍有效
- 补充：字段 Token 的用户表示与失焦解析由 ADR-0010 细化；本 ADR 中“稳定 Token”指内部绑定，不表示可以直接展示内部 ID

# 背景

线上灰度版虽有模板目录，却不能保存多个模板。模板卡片中放了编辑动作，编辑时目录不消失；外层组件、页面设置、设置多数是提示文字，又与设计器顶部组件和保存重复。字段名作为变量 ID 还使改名后绑定不稳定。局部隐藏按钮不能解决存储和状态冲突。

# 决策

1. 预览模式左侧管理同表多模板，右侧展示当前记录和当前模板，并放“编辑模板”。首次无保存模板时展示自动模板；保存的集合中恰有一个默认模板，初次打开默认选中它。新建模板是独立草稿，保存后成为独立条目，不覆盖原模板。切换、重命名、删除、设为默认均由外层仓库负责。删除默认项前必须显式选择另一个默认项；最后一项删除后回到自动模板。
2. 编辑模式隐藏模板目录。左侧为唯一产品级编辑操作区，统一承载数据源和组件：组件条目可以拖入真实画布创建组件；数据源条目不可拖动，只提供复制动作，内部携带稳定绑定，用户在文本组件内容编辑状态中看到并粘贴 `@字段名`。页面设置、设置及后续入口只有具备真实操作能力时才出现。右侧继续使用真实 `vue-print-designer` 画布与属性编辑，顶部只保留不重复的基础排版工具。
3. 保存只有一个用户可见的产品动作与一个持久化用例。引擎 `designer:save` 和 Ctrl+S 接入相同用例，不写其 localStorage 模板仓库。内置模板目录仍不启用。
4. 使用新的 base/table 范围 schema v2 集合键，保留旧 v1 base/table 及 table-only 键只读。v2 优先；首次写入以旧模板为默认项迁入 v2，验证原集合版本并清理运行数据。清理必须递归覆盖设计器运行变量、记录对象/ID、表格样本及凭证形态字段；含禁存数据的既有信封不得带病加载或被静默改写。迁移失败时原值不动，只读回退。bridge 不提供原子 CAS，并发竞态风险保持公开。
   正式 Base 实测 `bridge.getData` 对未设置的 v2、v1 两类键及无关键返回空普通对象 `{}`。仓库仅将该形态视为无值；带字段的未知对象仍拒绝读取和写入。bridge 无法区分真正存入的 `{}` 与未设置键，故不能用空对象承载合法模板；当前空键修复须通过正式环境首次保存和重开验证。
5. 新变量 ID 使用字段 ID 的插件命名空间；当前字段名仅作标签。旧按名称绑定的模板在当前字段名可唯一解析时兼容，保存后迁移；不能证明归属的旧变量不得猜测绑定。模板需保存字段 ID 到名称的非业务元数据，以支持后续字段改名。
6. 不重做设计器。优先使用公开 API；`1.7.39` 缺少移动/隐藏顶部组件区的公开 API，必要时版本固定的 DOM 适配必须有契约测试、明确作用域和升级退出条件。若无法稳定暴露组件操作，不能以只读说明面板冒充完成。
7. 同一文本组件的多字段组合采用“组件拖拽 + 数据源复制/粘贴”语义。不得以数据源拖拽创建文本元素，也不得把第二个字段映射为替换已有 `variable` 或重叠的新元素。编辑态显示友好字段标签，失焦与输出显示当前记录值，持久层仍保存稳定 ID；三层表示见 ADR-0010。数组/关联数据仍使用表格组件专用配置。

# 后果与验收

模板仓库、字段绑定、模式 UI 和脏草稿守卫必须一起迁移；旧阶段文档是历史证据而非现行要求。测试须覆盖 v1/v2 无损读取、不同表隔离、默认项删除规则、并发、字段改名、保存入口和正式灰度 Base 的新建/重开/打印回归。`BUG-0002` 保持开放，不在本 ADR 修改分页。
