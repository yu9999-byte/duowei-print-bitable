<title>ADR-0028 — 多维表格自动化动作与外部渲染服务</title>

# 状态

Goal v22 已接受，2026-10-12；2026-10-13 增补 OAuth 写授权、统一生产服务以及标准/后台双模式决策。既有单模式本地实现已通过，双模式尚待 TDD；正式可用仍受公网 HTTPS、后台配置、记录视图补丁和灰度验收门约束。

# 背景

多维打印当前是多维表格记录视图插件。模板保存在 bitable.bridge 的 Base 作用域存储中，打印和 PDF 由浏览器内的 vue-print-designer 1.7.39 完成。Goal v22 要让用户在多维表格自动化中选择一条触发记录和一个已保存模板，生成 PDF 或 PNG，并把结果用于后续修改记录步骤。

飞书官方自动化插件开发指南确认：

- 自动化能力通过独立的“多维表格插件 → 自动化操作”BlockType 注册；
- basekit.addAction 的 formItems、execute、resultType 分别定义配置表单、运行逻辑和后续步骤可消费的结果；
- Context 提供 Base token、触发 tableID、recordID、tenantKey、tenantAccessToken 和受限 fetch；
- SingleSelect.autocomplete 可以按当前 Base 异步加载模板选项；
- uploadAttachments 与 Attachment 结构可以把生成文件作为自动化结果返回；
- 上传附件需要应用具有多维表格管理权限，并在 addAction 中声明 permission.type = 2；
- 沙箱不能运行 jsdom、sharp，外部请求必须使用 context.fetch，且只能访问公网域名。

当前记录视图的 bridge.getData/setData 没有自动化服务端读取接口。把模板公开上传到一个只凭 tenantKey、Base token 或 Base URL 的接口会造成模板篡改风险，不能作为正式方案。

# 决策

采用三个运行单元和一个共享领域合同：

1. 记录视图插件继续负责模板设计。模板保存成功后，通过受身份校验的 Template Registry 接口同步仅含布局和稳定字段绑定的模板快照；不上传当前记录值、访问令牌或用户凭据。
2. 飞书自动化操作使用 SingleSelect.autocomplete 从 Template Registry 获取当前 Base/数据表的模板目录。首期只接受有 recordID 的单记录触发；定时触发等无记录场景明确拒绝。
3. 自动化 execute 在飞书沙箱内读取当前记录和字段元数据，规范化为最小渲染数据；tenantAccessToken 只用于飞书 OpenAPI，不发送给外部服务。
4. Renderer Service 使用与记录视图相同的模板合同和锁定引擎版本，在受控无头浏览器中生成完整多页 PDF 或仅第一页 PNG。
5. 自动化操作通过官方 uploadAttachments 返回附件，同时返回 success、status、error、artifactKey 等字段。该路径定义为“标准模式”：动作本身不写业务字段，结果供同一自动化中平台允许的后续步骤引用，至少支持飞书原生 SetRecord。
6. 新增“后台模式”：用户在动作配置中选择当前表的附件字段、必填状态文本字段和可选错误文本字段；动作创建持久任务，由 Worker 直接回写触发记录。最终文件不返回给同一自动化的后续步骤；需要通知时由状态字段变化触发另一条自动化。
7. 幂等键至少包含 tenant、Base、table、record、templateId、templateRevision、outputType、runMode 和记录内容摘要。标准模式复用有效产物；后台模式同时复用稳定任务和产物，不重复生成、上传或回写。
8. Template Registry 的写接口必须使用可验证的飞书身份会话或服务端签名。浏览器授权草稿只允许携带 Base、数据表和模板；写授权服务从真实会话取得 tenantKey、principalId 和 canWrite，校验草稿作用域后补成权威完整请求，并同时返回该 body 与其精确签名。记录视图必须原样提交该 body，任何浏览器提供或覆盖 tenantKey 的请求直接拒绝。没有完成身份校验前，只允许本地契约测试，不提供匿名写入口。
9. 写身份采用飞书用户 OAuth：一次性 state 与 PKCE 防重放，服务端交换 user_access_token，读取 open_id/tenant_key，并通过官方云文档权限接口验证用户对目标 Base 的 edit 权限。成功会话使用 `__Host-`、HttpOnly、Secure、SameSite=None Cookie，并绑定 Base/table；用户令牌和 App Secret 不进入浏览器、Registry 或 Renderer。
10. OAuth、Registry 和 Renderer 收敛为一个可部署服务；后台任务需要在同一服务增加持久任务入口和 Worker，但不得破坏现有固定路由、CORS 和鉴权边界。Renderer 使用隔离 Playwright 页面和同一锁定引擎，超时或 AbortSignal 取消必须关闭页面。

# 输出语义

- PDF：完整页面，页数与记录视图相同模板、同一记录的预览保持一致。
- PNG：首期只输出第一页，并在自动化表单和结果文案中明确说明。
- 自动化结果：附件数组、成功标记、状态文本、错误文本和稳定产物键。
- 标准模式：最终附件属于 Action 结果，可被同一流程后续步骤引用。
- 后台模式：最终附件、状态和错误直接写入用户选择的当前记录字段；同一流程只能得到受理结果，不得到最终文件。
- 自动化失败：业务可恢复失败返回 success=false 和可读错误，供后续条件/修改记录步骤消费；配置损坏、身份失败或数据越权直接使动作失败。

# 被否决的方案

- 在飞书自动化沙箱直接运行 vue-print-designer：沙箱缺少浏览器 DOM，官方还明确禁止 jsdom/sharp。
- 把 tenantAccessToken 发送给渲染服务：扩大令牌泄漏面，违反最小权限。
- 让用户粘贴模板 JSON 或内部模板 ID：不符合产品体验，也容易选错 Base/数据表。
- 用公开无鉴权接口接收模板：tenantKey、Base token 和 URL 不能单独作为写权限证明。
- 让记录视图自行提交 tenantKey 再由后端签名：前端声明不能证明租户归属，会形成可伪造的跨租户写入作用域。
- 为每个模板创建隐藏 Base 字段或业务记录：污染用户业务 Base，违反当前边界。

# 后果

- 当前单体前端仓库需要新增自动化 action 包、Renderer Service 和 Template Registry 端口。
- 正式联调前需要在现有“多维打印”应用中新增自动化操作 BlockType、配置可访问的 HTTPS 服务、申请附件上传所需权限；这些外部变更必须另行取得用户授权。
- 首期仍不支持批量自动化、Office 模板、多租户商业扩容或签名。后台模式只处理单条触发记录，不等同于批量自动化。
- 单实例 MVP 需要持久卷保存 Registry，并以串行 Chromium 页面优先保证正确性；水平扩容前必须改用事务数据库和经过容量验证的任务队列。
- App Secret、Registry 读写签名密钥和 Renderer 签名密钥只能由生产托管环境注入。没有真实 HTTPS 部署、OAuth 回调配置和健康检查证据时，记录视图补丁不得上传。

# 一手证据

## 2026-10-14 权限范围修订

独立测试 Base 的模板同步连接曾因 OAuth 单独请求未开通的 `docs:permission.member:auth` 返回飞书 `20027`。官方[判断用户云文档权限](https://open.feishu.cn/document/server-docs/docs/permission/permission-member/auth.md)说明该接口接受 `bitable:app`（满足任一权限），且可对 `type=bitable&action=edit` 返回当前用户的 `auth_result`。应用用户身份已开通 `bitable:app`，故 OAuth 改为只请求现有权限；服务端仍以用户令牌核验身份、租户和目标 Base 的编辑权。不得仅凭拥有 `bitable:app` 或能读取 Base 元数据就签发写入授权。TDD 中先将 OAuth scope 断言改为 `bitable:app` 并观察两套测试失败，再修改服务与共享实现使其通过。此修订不新增后台权限，正式连接与 E2E 仍须实测。
