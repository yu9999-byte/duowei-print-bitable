# 双入口共享模板与保留式迁移

日期：2026-10-19。状态：共享服务与双入口已灰度；正式测试 Base 的 6 个旧模板已保留式迁移，跨入口模板操作、预览、PDF 和浏览器打印核心验收通过。第二成员、只读授权及跨表/多选扩展矩阵未验证。

## 授权与目标

用户已明确同意增加两入口共享模板存储适配，并在保留旧模板的前提下制定迁移方案。保持原 Goal：数据表视图与详情入口共用数据源规则、界面和功能，同一 Base/table 的模板一致。不得恢复暂停的自动化任务、扩大灰度或顺带增加权限。

## 设计

两入口共用 TemplateRepository，服务端以可信会话解析出的 tenantKey 加 baseId、tableId 定位完整模板集合。集合包含模板 ID、名称、画布、默认模板和按模板保存的有序批量记录 ID；不保存业务记录值。自动化 Registry 是另一种模型，不能直接替代集合仓库。

共享模式通过 DUOWEI_SHARED_TEMPLATE_ENDPOINT 构建参数显式启用。未配置时原记录入口继续使用原 bridge。启用后所有集合读取、改名、保存、删除、默认项和批量记录修改都走同一存储，不做失败后写回 bridge 的降级。浏览器只携带会话，不包含服务密钥或客户端提供的 tenantKey。

HTTP 使用 POST、credentials include、no-store。服务端验证真实会话、Origin、Base/table 权限及请求大小，并设置响应 Cache-Control: no-store。已将 authorize 端口接入真实飞书用户信息和 Base 编辑权限校验，不使用测试身份。插件通过用户点击打开独立授权弹窗，弹窗同源携带 cookie 请求接口，再通过严格校验 source、origin、protocolVersion 和 requestId 的 postMessage 回传，避免依赖插件 iframe 的第三方 cookie。弹窗关闭后须重新连接，不做旧库降级写入。

生产会话和一次性授权状态存于增量表，内容 AES-256-GCM 加密、查询键散列、设置有效期；授权状态原子消费，token 不持久保存。PKCE 使用官方当前 authorize 接口配套的 v2 JSON token 接口。真实授权、共享读写和两个宿主弹窗消息闭环已在正式 iframe 验收；连接窗口须保持开启。现有 OAuth 边界要求 Base 编辑权限；不能据服务单测宣称只读成员的完整授权流程已经可用。

数据库按 tenant/base/table 原子比较 revision 后写入。首次写入只允许目标不存在；后续更新必须匹配旧版本。过期版本返回 409。客户端重新加载后由用户决定是否重做修改，禁止静默覆盖。独立增量模板表及 OAuth 表已部署，未改旧表。临时 PostgreSQL 的并发/隔离/中文实测已通过；线上旧模板迁移、共享模板保存/改名/默认项/删除已通过实际操作回读。

## 迁移步骤

1. 先关闭或刷新仍可能写旧 bridge 的旧版本窗口。在原记录插件内读取旧模板，由现有解析器验证版本、画布和校验和。盘点所有模板、默认项、批量记录顺序、旧集合 revision 及目标 revision。读取失败停止，不把失败当空库。
2. 迁移前保留原始存储原文备份及已解析集合快照，备份访问权限与模板相同，不在公开日志输出模板正文。旧 bridge 的任何键均不删除或覆盖。
3. 迁移前让两入口停止本作用域编辑，并确认没有其他旧版本窗口继续写入。再次读取旧 revision；变化则重新盘点，不能沿用旧计划。仅凭单次客户端读取无法锁住其他旧窗口，这是正式迁移必须实测的门槛。
4. 空目标采用一次原子整集合导入，保留 ID、名称、时间、默认项、画布、批量记录顺序与校验信息；旧 schema v1 先使用现有兼容解析，再构建合法 v2 集合。不逐条 upsert，避免丢默认项、时间或产生半导入。
5. 目标已与源完全一致则无需重复导入。目标非空且内容不同一律人工处理；相同 ID 的画布、名称、时间或批量记录任一不同均列冲突，不用“最后修改时间较新”自动覆盖。已存在但空的目标也不视为未迁移，以免复活已删除模板。
6. 服务端提交后回读完整集合逐项核对。若请求超时，先回读判断是否已提交，不盲目重试或反向覆盖。回读未完成时保持迁移待核对状态。
7. 当前灰度两个入口均配置共享服务。详情入口连接后在列模板前执行保留式迁移；数据表入口发现共享目标不存在时，阻止创建并提示先从详情入口连接，避免提前建空库阻断旧模板导入。空源也导入合法空集合，以区分“确认过的空库”和“尚未迁移”。核对两入口读取、改名、保存、删除及默认项一致后完成验收。

`planTemplateMigration` 提供只读盘点和冲突分类；`migrateLegacyTemplates` 已实现实际原文备份、整集合 CAS 导入、源版本复查、目标回读及确认标记。备份已有但与当前源不同则停止；确认标记保存源 revision、导入 revision 与备份键，后续不覆盖共享库的新改动。检测旧源迁移后改变会阻断自动迁移。客户端不能锁住其他旧窗口，关闭或刷新旧窗口仍是上线操作前提。

正式测试 Base `CjjybEbM8aL9rlsGhfocfRCMnFe` / `tblUdB1VhaFIkGKu` 已从详情连接触发实际迁移：6 个模板，source/imported revision 均 `fnv1a32:ed50147c`，ID、默认项、画布校验和和有序批次均保留。三个原 bridge 键与原文备份逐字相同。数据表创建、保存、改名并设置临时默认后，详情连接保留共享新改动；恢复原默认、删除临时模板后，共享 revision 恢复原值，未改原模板或业务字段。其他 Base/table 尚未执行批量迁移，按上述步骤逐作用域进行。

## 回滚

切换前失败：停止导入，保留旧插件及全部旧 bridge 内容；目标已提交时保留证据，不自动删除。

切换后失败：先停止编辑，导出共享库中切换后新增或修改的完整集合，核对两边差异。不能简单清空 endpoint 切回旧 bridge，否则会看不到新模板；需制定显式回灌或修复共享服务方案并验证，再恢复编辑。旧数据保留只保证可恢复的基础，不代表无损回滚已经完成。
