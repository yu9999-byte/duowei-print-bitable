<title>ADR-0005 — 动态数据源模型</title>

- 状态：partially superseded by ADR-0009（动态分组仍有效；字段名 ID 已取代）
- 日期：2026-09-22

# 背景

真实插件中展示的数据源仍是错误或陈旧的 Demo 变量。代码虽然调用了 `setTestData/setVariables`，但把引擎的 `ext.availableVariables` 写成字符串数组；锁定版 `vue-print-designer@1.7.39` 的变量面板实际读取 `{id,label,isArray?,children?}` 对象树。活动模板还会持久化旧目录，使错误跨会话延续。

# 决策

1. 产品术语统一为“数据源”，分为“字段”和“系统”。
2. “字段”目录只由 `table.getFieldMetaList()` 当前返回的 SDK 字段元数据动态生成，保持返回顺序，不受当前视图隐藏字段影响，也不在生产代码预置订单、客户等业务字段。
3. 关联字段标记为数组数据源；字段 ID 沿用字段名以匹配当前引擎变量绑定。
4. “系统”目录由插件维护，使用 `__duowei_system_*` 命名空间；当前包含打印日期。
5. 活动模板持久化排版，但不拥有当前数据源目录。每次绑定都用当前上下文覆盖 `ext.availableVariables`，防止旧模板带回 Demo/其他表字段。
6. 不 fork 或自制打印设计器；通过 DesignerAdapter 将引擎主标题“可用变量”适配为“数据源”。

# 后果

字段新增、删除或切换表后重新读取即可得到新目录；旧模板排版继续复用。旧版 `@打印日期` 暂保留运行时兼容别名，新模板统一使用命名空间 ID。引擎内部 DOM 文案适配依赖锁定版本，升级引擎时必须做 E2E 回归。

# 验证

`tests/data-sources.test.ts` 覆盖动态字段、字段/系统分组、数组字段和旧目录刷新；`tests/designer-adapter.test.ts` 覆盖真实值注入、系统命名空间和术语。修复包已上传，后台已选择保存小组件 `1.0.3`，并随应用版本完成灰度发布；真实插件已进入 `PO-0001` 并显示真实值，数据源目录的逐项人工截图仍待补齐。

# 2026-10-04 补充：系统打印日期的时区

正式环境当地时间为 `2026-10-04 02:05 +08:00` 时，连续预览和下载 PDF 显示系统打印日期 `2026-10-03`（BUG-0008）。网关的 ISO UTC 时间本身正确，错误是运行时变量直接截取该字符串前十位。

- 保留 `PrintJob.generatedAt` 作为本次任务生成时刻，不改变网关时间格式或模板 schema。
- 只在运行时数据源边界使用标准 Date 本地日历年/月/日转成 `YYYY-MM-DD`；本地时区为用户浏览器时区，不硬编码中国时区，不逐条或导出时重新读取时钟。旧任务复用时日期仍归属于原任务生成时刻。
- 系统命名空间与旧 `打印日期` 别名保持兼容；存在同名表字段时不覆盖其真实值。无效生成时刻显式失败，不输出 `NaN` 或猜测日期。
- 用独立 Node 子进程的 `TZ` 测试正/负时区跨日、UTC、夏令时、批次一致性及同名字段，不改操作系统时区或全局测试进程环境。本地 Green 与正式部署/验收分别记录。
