# 背景

用户明确要求多维打印不是独立 Demo，而是嵌入多维表格、打印某条记录字段的插件。早期文档把入口描述为“侧边栏扩展脚本＋记录选择器”，且项目只有 Vue/Vite 网页入口；这不能证明它是飞书开放平台的插件代码包，部署在子路径时根绝对 `/assets/...` 也可能直接造成空白页。

# 决策

采用飞书开放平台“多维表格插件→记录视图”能力。单条打印的上下文来自记录视图宿主 `bitable.base.getSelection()` 的 `baseId/tableId/viewId/recordId`；仅批量打印调用 `bitable.ui.selectRecordIdList(tableId, viewId)`。

工程使用官方记录视图链路：

- 项目级 `app.json` 绑定市场应用 `cli_aa3a18dc8eb95bd1`，不存 App Secret。
- `record-view/block.json` 绑定该应用中记录视图能力的真实 `BlockTypeID` `blk_6ab0a4c12f818bde89ca4e8a`；该值来自控制台，没有伪造。
- Webpack 使用 `@lark-opdev/block-bitable-webpack-utils` 生成 `offlineWeb` 代码包，资源 `publicPath` 为 `./`。
- 生产构建把现有 SDK 导入 alias 到 `@lark-opdev/block-bitable-api`；Node 单元测试保留无宿主即可加载的 SDK，以防 Block SDK 在 Node 中因“only running in Block host”失败。
- 通过 `opdev upload` 上传 `record-view/dist`，再在控制台选择小组件版本、配置权限并发布/安装；没有这一步，本地页面不能称为插件闭环。

# 一手证据

- [多维表格插件概述](https://open.feishu.cn/document/base-extensions/base-extension-introduction)：官方将打印示例归为记录视图插件；记录视图在展开记录详情后添加。
- [多维表格记录视图开发指南](https://open.feishu.cn/document/base-extensions/base-record-view-extension-development-guide)：要求添加“多维表格插件→记录视图”，记录 App ID/BlockTypeID；以 `opdev create ... -a bitable-extensions -s record-view` 初始化，使用 Webpack、`@lark-opdev/block-bitable-webpack-utils`、`@lark-opdev/block-bitable-api`，通过 `opdev upload ./dist` 上传。
- 官方 Vue 模板 `record-view-vue_0.0.3`：`block.json` 含 `blockTypeID`，Webpack 生产 `publicPath: "./"`，并使用 `BitableAppWebpackPlugin/opdevMiddleware`。
- 本地构建已生成 `record-view/dist/project.config.json`（App ID）和 `index.json`（真实 BlockTypeID、`blockRenderType: offlineWeb`）；Opdev 上传成功且控制台已保存小组件 `1.0.0`，但这仍不是 E2E 通过。

# 已确认的空白页原因

原 Vite 产物 `dist/index.html` 引用 `/assets/...`，且工程缺少 App/Block 清单与 Opdev 上传链。该页面在本地 Vite 服务可显示，但不是记录视图插件代码包；把它放在子路径或直接当静态文件打开可能因资源路径失败而空白。新 Webpack 产物已使用 `./assets/...`，并生成飞书插件清单。
