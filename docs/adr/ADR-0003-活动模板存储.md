<title>ADR-0003 — 每表活动模板存储</title>

- 状态：superseded by ADR-0009（v1 只读兼容；当时的 bridge 证据保留）
- 日期：2026-09-21

# 背景

MVP 要求每个 base/table 一个可跨会话复用的活动模板。原文档写“附件或云盘”，但未确定数据结构、授权、共享边界和版本迁移。引擎自身 localStorage/远程 CRUD 不能直接证明满足跨用户/表隔离。

# 候选

1. Base JS SDK 的 `bitable.bridge.getData/setData`：文档确认同一文档同一插件共享；按 tableId 分键，待验证容量、写权限与跨会话。
2. 经授权的云端存储：按 base/table 键保存版本化 JSON，服务端校验当前用户访问权。
3. 飞书云盘/附件：仅当能证明稳定寻址、写入权限与并发冲突处理后采用。

# 必须验证

- 同表重开与不同表隔离；编辑者写入和只读用户行为。
- 模板 schema、引擎版本、更新时间、校验和/迁移；旧模板失败时不覆盖原数据。
- 不保存真实记录值和令牌；并发编辑不静默丢失。
- 一表一个活动模板；多模板管理不在 MVP。

# 决策门

在 ADR-0002 宿主/鉴权确认后，针对可用存储做实际写入/读取测试，再选方案转 accepted。未确定前可以定义 TemplateRepository 契约和单测，但不得声称持久化完成。

# 当前实现证据

- 使用键 `duowei-print:active-template:<tableId>`，通过 `bitable.bridge.getData/setData` 每表存一个活动模板。
- schema v1 信封记录引擎名/版本、tableId、更新时间、校验和；不兼容或校验失败时拒绝加载且不覆盖原值。
- 真实飞书首轮验收发现历史存储不含可识别的 schema v1 信封。读取失败时返回只读回退结果：保留原存储，使用自动模板继续绑定当前字段和值，并禁用保存，避免旧模板阻断打印数据闭环或被静默覆盖。
- 保存使用期望校验和拦截已经发生的旧版本覆盖；bridge 未确认写入时报告失败。SDK 未提供原子 compare-and-set，两窗口同时完成读、后写覆盖的竞态尚未消除；本条“并发编辑不静默丢失”尚不满足，不能据单测将 ADR 转 accepted。
- 保存前除运行态 `testData`、`variables` 和表格样本 `data` 外，还递归移除 `runtimeValues`、documents/records/recordId(s)/recordData/recordValues，以及大小写、下划线、连字符变体下的 Authorization、刷新令牌和各类 access token。已有信封若含禁存运行数据则拒绝读取且不回写。用户主动写入模板的固定内容不可能仅靠结构清理判定是否敏感，验收仍须检查。
- 2026-10-06 当前定向安全/仓库测试 16/16、全量 160/160 与生产构建通过；生产源代码另有静态门禁，禁止 console 输出、localStorage/sessionStorage 和直接 Authorization/Bearer 构造。该证据仅覆盖仓库及代码边界；跨会话、跨用户、权限、容量与显式迁移仍需真实飞书测试，本 ADR 的历史状态不变，现行多模板决定见 ADR-0009。
