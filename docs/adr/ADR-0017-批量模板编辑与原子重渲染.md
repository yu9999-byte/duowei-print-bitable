<title>ADR-0017 — 批量模板编辑与原子重渲染</title>

- 状态：accepted（Goal v9 产品、架构与本地候选已完成；正式环境验收待另行授权发布）
- 日期：2026-10-08
- 取代：ADR-0012 中“批量预览只读、模板编辑只能先退出批量”的决定
- 保留：ADR-0011 的批次候选原子提交、失败恢复和 canonical rendered pages；ADR-0009/0010 的模板单一事实源、稳定 Token 与数据安全规则

# 背景

现行工作台把 `batch-ready` 强制投影为只读 `batch-preview`，隐藏编辑入口并拒绝保存。该规则解决了早期“旧批次页面与新模板混用”的风险，但把“当前模板应用于多条记录”错误地拆成了两个互斥流程：用户必须退出批量、编辑单条模板、再重新选择记录。

竞品“排版打印”的批量页面表明，左侧批次目录可以持续表达当前模板、排版方式和已选记录；右侧模板区域在批量预览与模板编辑之间切换。用户确认 Goal v9：批量不是一次性只读结果，而是同一模板和同一批记录组成的工作会话。

# 决策

1. `WorkspaceSurface` 从三个表面扩展为 `single-preview`、`single-edit`、`batch-preview`、`batch-edit`。`BatchPrintSession` 继续拥有已提交记录 ID 和摘要；`WorkspaceMode` 决定右侧处于预览还是编辑，二者不再相互覆盖。
2. `batch-preview` 与 `batch-edit` 共享同一左侧批次目录。目录持续显示记录数、当前模板、排版方式和记录摘要，不因右侧进入编辑而卸载、清空或替换为模板目录。
3. 批量预览提供唯一“编辑模板”入口。进入后只切换右侧模板区域：展示真实 `vue-print-designer`、唯一数据源/组件操作面和唯一保存动作；打印、PDF、重新选择和退出批量在未保存编辑期间不可作为有效输出动作。
4. 批量编辑修改当前模板本身，不创建记录级模板或批次模板副本。持久化仍调用同一个 `TemplateRepository.upsert` 用例，模板不得保存当前批次的记录 ID、记录值或运行变量。
5. 保存分为两个连续但可区分的提交步骤：先持久化模板，再使用当前 `PrintJob` 和新模板生成候选 canonical rendered pages。只有整批重渲染成功，右侧批量预览才原子替换；失败时保留可继续编辑的草稿/已保存模板状态以及保存前最后一份可打印批次，不显示空白工作区，也不把新模板与旧页面标成同一版本。
6. 默认、标签、连续三种布局均从模板本身推导并走既有渲染器；保存后不得重选记录或把布局降级为默认模式。
7. 返回批量预览、重新选择、退出批量、切换模板或宿主上下文均复用未保存草稿守卫。保存失败停留在编辑态；放弃修改恢复进入编辑前的模板并重新显示原批次；继续编辑不改变批次。
8. 锁定引擎把普通 Enter 当成提交。适配层在 Shadow DOM 捕获阶段仅接管无修饰键的 Enter，向 textarea 插入换行并派发 `input`；失焦仍由引擎提交并触发数据源同步。Ctrl/Cmd/Alt+Enter 与 Escape 保留引擎语义。多行内容在持久 Token、友好标签、当前值和输出四层转换中必须保持换行。

# 取舍与边界

- 左侧“批次目录保持不变”不等于在批量态开放新建、删除、重命名或切换其他模板；这些动作会改变批次事实源，继续留在单条预览模板目录。
- 批量编辑需要数据源和组件，但不能用它们替换左侧批次目录；操作面应位于右侧编辑工作区内部，并继续复用既有复制/拖入回调。
- 模板成功落库而重渲染失败时，产品必须明确区分“模板已保存、批次预览未更新”，旧批次只作为恢复证据保留，不能伪装成新模板结果。
- 本决策不改变最多 50 条、宿主读取超时、PDF/打印算法、模板 schema、权限或发布范围。
