# 背景

项目要求在真实飞书多维表格场景直接集成 `vue-print-designer`，不得自制替代设计器。原文档把 API、批量能力和许可证描述为推测或仅在商业化前处理。当前“多维打印”是飞书市场应用，已经仅向企业 `F225904757` 灰度，未来产品形态可能包含多租户安装和对外分发，因此不能只按个人项目或单企业内部系统判断授权范围。

# 引擎决策

使用真实 `vue-print-designer` Web Component，业务层与引擎间设置 DesignerAdapter。开发期间锁定明确 npm 版本，不使用 `latest`。批量优先验证引擎公开的 `getBatchPdfBlob`、`exportBatchPdf`；浏览器打印由适配层使用引擎 `getPreviewHtml()` 的渲染结果在当前插件文档调用一次 `window.print()`，避免 Edge `window.open(blob:)` 和 `blob:` PDF iframe 路径；不能以逐条循环弹窗验收。模板 JSON 由安装版 `getTemplateData()` 样本反推并契约测试，不以 TD 伪结构生成。

# 事实与结论边界

1. **事实**：npm 包和同版本仓库 `package.json` 声明 `AGPL-3.0-only`；AGPL 本身并不以“非商用”作为使用条件。
2. **事实**：作者同期仓库文件与官网商业页面又明确表示免费版仅个人非商用、企业使用和品牌变更需商业授权。
3. **事实**：当前产品是飞书市场应用；若向多个租户安装或销售，已超出官网“标准版仅单企业内部使用、不含对外分发”的公开描述。
4. **结论**：上述材料之间存在需要权利人或法务解释的表面冲突。本项目不自行断言任一文本必然优先，也不把“AGPL 允许商业使用”推导为当前企业市场应用必然无需授权。本 ADR 不是法律意见，授权门保持 `unresolved`。

# 当前约束与发布门

- 可以继续不扩大范围的本地开发、自动化测试，以及既有单一灰度企业中的受控技术验证；这些活动只用于取得技术证据，不代表已经取得企业使用许可。
- 在取得权利人书面授权或法务书面结论前，不得扩大灰度企业、全量发布、商业收费、向其他租户分发，也不得宣称产品已满足商业上线合规条件。
- 官网“标准版”公开范围只覆盖单企业内部使用，不能默认覆盖飞书市场应用或多租户分发；如继续该产品形态，至少需要权利人明确高级版或其他定制许可的覆盖范围。
- 若授权不能覆盖拟定用途，先形成引擎替换/自研/范围调整方案和迁移成本，由用户确认后另立 ADR；不得在本 ADR 中静默替换引擎。

# 权利人书面确认清单

联系权利人或提交法务审查时，必须把以下问题及答复原文归档；本项目不代用户发送或提交：

1. 哪一种许可明确覆盖飞书开放平台的“市场应用”形态？
2. 是否允许同一应用被多个企业租户安装、使用，并由开发者收费？
3. 是否允许将 `vue-print-designer` 的前端构建产物随插件包分发到飞书托管域名？
4. 产品使用“多维打印”名称和自身品牌时，是否属于允许的白标/品牌变更？
5. 是否必须保留 PrintDot 或原作者版权标识，保留位置和展示要求是什么？
6. 商业授权与 AGPL-3.0-only 的适用关系是什么；是否要求公开“多维打印”全部或部分源代码？
7. 授权域名应如何填写：飞书托管的 `feishupkg.com` 等动态域名、应用 ID 或其他稳定标识？
8. 当前仅企业 `F225904757` 的灰度技术验证是否属于许可的评估范围；如不是，允许的评估方式和期限是什么？
9. 标准版、高级版或定制许可中，升级、版本更新、售后和授权主体/期限分别如何约定？

# 复议触发

收到权利人/法务书面结论；锁定版本 API 与同版本证据不同；飞书容器不能加载或打印；批次方法无法满足一次任务；产品从单灰度企业扩展到其他租户或收费。触发后附原始证据和选项更新本 ADR；未获得结论前不得把授权门改为 `accepted`。
