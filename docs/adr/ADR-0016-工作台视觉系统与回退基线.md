<title>ADR-0016 — 工作台视觉系统与回退基线</title>

- 状态：accepted（本地实现；正式效果待发布验收）
- 日期：2026-10-07
- 关联：SPEC-UX-08、BUG-0005、PHASE-05

# 背景

工作台功能逻辑已经形成预览、编辑、批量和模板目录的单一流程，但视觉仍由历史局部 CSS 叠加而成：字体、字号、按钮层级、模板状态、纸张区域、加载/错误状态和窄容器缺少统一规则。直接在 `main` 上试错会让视觉修改与已验证业务逻辑难以分离，也缺少可远程恢复的基线。

# 决策

1. 先将完整当前版本提交到 GitHub，并用 annotated Tag `baseline-pre-style-redesign-2026-10-07` 锁定 commit `2a2a8efb32b4bd2c791f50ba3e569de386f5eacd`。
2. 视觉改造只在 `codex/modern-workbench-style` 进行；失败时以该 Tag 对比或放弃分支，不在 `main` 上试错。
3. 使用“飞书原生工具感 + 纸张工作台”：中性浅色表面、单一蓝色强调色、真实纸张阴影、克制圆角和一套 CSS Token。
4. 打印为主输出，PDF 为次输出；读取、选数和退出为普通操作。模板管理次要动作默认弱化，悬停和键盘聚焦时展示。
5. 编辑模式仍使用真实 `vue-print-designer@1.7.39`；外层只重排已有入口并统一主题，不重写画布、数据源、模板、打印或 PDF。
6. 锁定 `src/core/**`、`src/engine/**`、`src/host/**`、依赖和应用配置。仅允许 `App.vue` 的展示结构/主题调用、`style.css`、视觉测试与文档改变。
7. 正式上传和灰度不是本阶段自动动作；候选完成后先汇报，取得明确确认才进入既有发布流程。

# 后果

- 视觉变化可单独评审、提交和回退，不把功能提交混进样式分支。
- 工作台明暗、状态和操作层级有统一契约；窄容器和键盘用户有明确保护。
- 设计器主题固定浅色会覆盖其“跟随系统”表现，但与当前外层工作台保持一致；未来若引入全局深色模式，必须让外层和设计器一起切换，不能只恢复设计器自动主题。
- 本地截图和自动化不等于正式飞书 E2E；发布前问题保持“本地候选已修复”。

# 复议条件

若正式记录视图宽度导致顶部/侧栏操作裁切，或设计器浅色固定与产品级主题需求冲突，先在样式分支补规格与视觉用例再调整；任何需要改变业务状态或输出算法的方案必须另立 ADR，不能借视觉改造越界。
