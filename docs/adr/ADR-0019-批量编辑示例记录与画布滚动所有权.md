<title>ADR-0019 — 批量编辑示例记录与画布滚动所有权</title>

- 状态：partially superseded by ADR-0020（画布高度链与滚动所有权仍有效；“示例记录 i/N”及上一条/下一条已被废弃）
- 日期：2026-10-08
- 补充：ADR-0017、ADR-0018

# 背景

批量预览会展示全部已选记录，但真实设计器只绑定第一条记录。用户进入批量编辑后只能看到一条，界面既没有说明它是公共模板的示例数据，也不能切换检查其他记录；这容易被理解为另外两条丢失或只能编辑一条。与此同时，工作台外层把设计器宿主设为 `overflow: hidden`，`print-designer` 只有最小高度而没有确定高度，导致锁定版设计器内部 `.canvas-scroll` 无法取得完整可用高度，纸张底部在编辑态被裁切。

竞品“排版打印”的公开批量说明和界面证据均采用“一份模板套用多条记录”：批量预览展示多条结果，编辑入口编辑公共模板单元，而不是给每条记录创建独立模板。多维打印保持这一模型，并补充显式示例记录切换来消除当前歧义。

> Goal v13 复核后确认，“示例记录切换”仍把完整批次压缩成单条画布，与竞品全量滚动查看/编辑及用户预期不一致。批量全量可编辑投影和公共模板回收以 ADR-0020 为准；下述示例索引决策只保留为 Goal v12 历史证据。

# 决策

1. `batch-edit` 始终编辑当前选中的一份公共模板；不创建记录级模板、记录级草稿或第二套画布。
2. 工作台维护非持久化的示例索引，工具栏显示“示例记录 i/N · 主字段值”并提供上一条/下一条。索引只引用 `BatchPrintSession` 与当前 `PrintJob.documents` 的相同顺序。
3. 切换示例调用 DesignerAdapter 的运行时变量恢复能力，只替换 `setTestData/setVariables` 数据。不得调用 `loadTemplateData`，不得修改持久模板、模板校验和、草稿脏状态、批次会话或 canonical pages。切换失败保持原索引和草稿。
4. 默认模式的编辑对象是页面模板；连续模式是一个重复单元；标签模式是首个标签单元。保存仍走 ADR-0017 的单一持久化与原子重渲染路径，用同一模板重新生成全部记录。
5. `WorkspaceShell → canvas-stage → designer-host → print-designer` 建立 `height: 100%` 和 `min-height: 0` 的完整高度链。外层只限定工作区边界，真实设计器内部 `.canvas-scroll` 是编辑画布唯一滚动所有者；不在宿主外再加一个纵向滚动层。

# 后果与验收

- 示例记录状态不进入模板仓库，也不改变打印/PDF算法。
- 自动测试覆盖索引归一化、边界按钮、标签回退、切换时模板不重载、运行数据更新、失败保持，以及 App 高度/滚动契约。
- 真实设计器验收至少使用三条记录，逐条切换并在未保存修改存在时确认草稿不丢；在 932×540 和 700px 宽容器到达纸张四边及底部。
