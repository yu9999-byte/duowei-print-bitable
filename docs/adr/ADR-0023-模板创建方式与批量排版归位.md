<title>ADR-0023 — 模板创建方式与批量排版归位</title>

- 状态：accepted / implemented（Goal v15）
- 日期：2026-10-10
- 取代：ADR-0014 的“连续模板是独立模板类型”、ADR-0018 第 6 条的三种模板创建、ADR-0022 第 5 至 8 条的模板级排版新建
- 保留：ADR-0018 的模板目录/编辑态职责、ADR-0022 的九组件与原生属性面板、既有三种输出算法

# 背景与证据

竞品“排版打印”的正式 Base 与官方说明显示：左侧目录表达当前数据表共享的一组打印模板；批量打印先选中一个模板和多条记录，再在当前模板内选择默认、连续或标签排版。默认、连续、标签不是创建模板时的模板类型。竞品的新建入口提供空白或自动生成等创建方式，而不是“连续模板/标签模板”。

当前实现把这两个维度合并：模板目录可新建默认、连续、标签模板，编辑侧栏切换排版会创建另一份草稿。该模型会增加重复模板、让批量设置跨模板串联，并阻碍后续共享、权限和模板资产管理。

# 决策

1. 模板与批量会话分离：模板保存名称、画布、组件、纸张及每模板批量设置；批量会话只保存当前模板、已选记录与本次输出状态。
2. 新建模板首期只有“空白模板”和“自动生成模板”。两者都是创建方式，不是打印排版。
3. 默认、连续、标签是当前模板的 `BatchLayoutMode`。切换模式保持模板 ID 与模板集合数量不变，不创建目录项，也不修改其他模板。
4. 每个模板独立保存最后使用的批量排版及其必要设置。记录 ID、记录值和批量投影实例不得进入模板存储。
5. 单条预览与编辑只操作当前模板的基础画布；进入批量后才展示排版模式。批量预览保持模板目录，批量编辑隐藏目录并保留唯一数据源/组件/批量设置操作区。
6. 历史普通、连续、标签模板均无损读取。旧连续标记转为运行时有效视图；旧标签根画布保存在 `labelTemplate` 变体中，并补充可用于默认/连续的普通基础画布。迁移不删除模板或标签内容，也不把“显示默认、实际标签”的矛盾状态写入仓库。
7. 模板集合仍以 `baseId + tableId` 为作用域。在缺少真实双成员证据前，不把“键相同”写成“共享已验收”。用户于 2026-10-10 将该验证及权限边界移出 Goal v15；技术设计不变，但本项不再是本 Goal 完成门。

官方 `bridge.setData` 文档明确表述为“在当前 base 中存储自定义内容”，`bridge.getData` 获取该内容；项目安装的 `@lark-base-open/js-sdk@1.0.2` 又将其声明为按 key 读写“持久化数据”。这证明当前方案不是浏览器本地或显式用户级存储，支持继续以 Base 原生存储作为首选路径；但官方页面没有直接承诺“两个成员必然读取同一值”，因此 `E2E-TPL-SHARE-01` 仍不可由文档或替身测试关闭，只能标为 Deferred。

# 实现和迁移边界

- 模板创建与批量排版使用不同类型、函数和 UI 入口，禁止再次共用 `TemplateLayoutKind` 代表创建方式。
- 既有默认、连续、标签输出算法继续复用；本 ADR 不重写 `vue-print-designer`、打印/PDF算法或原生属性面板。
- 标签模式需要的网格及连续模式需要的固定高度约束属于当前模板的批量设置；不以创建第二个模板绕过兼容检查。
- 切换候选必须按“绑定候选→完整渲染→编辑态全量投影→持久化→提交 UI”执行；失败时恢复旧有效画布，并保留原模式、记录会话和上一份可打印预览。

# 验收

- 新建菜单恰好包含“空白模板、自动生成模板”。
- 切换默认/连续/标签前后模板 ID、模板数和其他模板校验和不变。
- 两个模板保存不同批量模式后重开可分别恢复。
- 历史三类模板可读取、预览、编辑和保存且内容不丢失。
- 同表双成员共享与权限边界标记为 Deferred：用户已移出 Goal v15，未验证、未通过、不阻塞本 Goal；未来恢复时若平台存储不是共享作用域，必须记录证据并另行评估最小服务端方案。
- SPEC、SDD、TEST、TRACE、TODO、CHANGELOG 与实现一致；全量测试和生产构建通过后才可申请正式灰度验收。
