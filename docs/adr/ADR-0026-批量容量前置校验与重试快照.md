<title>ADR-0026 — 批量容量前置校验与重试快照</title>

# 状态

Accepted（本地范围），2026-10-11。事务前置校验、不可变重试快照、App 原批次重试接线和本地回归已完成；正式飞书 1/10/50/51 条与自然超时现场仍待另行授权。

# 背景

现有页面在官方选择器返回后先判断 50 条上限，但 `prepareBatchCandidate` 自身要等 `loadJob` 返回后才由 session commit 拒绝 51 条；安全边界依赖单一 UI 调用方。超时反馈虽显示“重试批量读取”，按钮实际重新打开选择器，用户必须重新选择，且系统没有可验证的原失败请求快照。

# 决策

1. 记录集合在候选事务入口先去空、去重、冻结并校验 1 至 50 条；超过上限在任何数据读取或渲染前拒绝。
2. `prepareBatchCandidate` 接收明确的 requestedRecordIds，并将其传给 loader；读取结果必须与请求集合顺序一致后才继续。
3. 超时保存纯内存 `BatchRetryRequest`，内容仅为上下文 ID、模板 ID 和记录 ID；不保存业务字段值或模板内容。
4. 重试不重新打开选择器，只重放同一快照；上下文或模板变化立即使快照失效。
5. 默认、连续、标签继续共用一个候选事务，只在 render 回调内选择布局，不建立三套失败恢复代码。

# 拒绝方案

- 不只保留 App 中的 51 条 if，因为其他调用方或未来重构可能绕过。
- 不把失败请求写入模板仓库、浏览器存储或 Base bridge。
- 不在重试时清空旧批次，也不允许迟到请求覆盖新成功结果。
- 不通过重新打开选择器冒充“重试同一批”。
