<title>ADR-0027 — 字段生命周期统一解析与输出降级</title>

# 状态

Accepted（Goal v21 候选完成；尚未上传或发布）

# 背景

模板持久层已经使用稳定字段 ID，并能在编辑态把 ID 显示为当前 `@字段名`。但输出准备此前另走 `resolveDataSourceTokens`：字段删除后，单条、默认批量、连续和标签输出可能重新出现 `@__duowei_field_<ID>`；字段仍在元数据中但当前记录没有可读值时，也会被当成空字符串。编辑态正确并不能保证最终打印正确。

# 决策

1. 一个 `PrintJob` 与一份模板只创建一套 `DataSourceTokenCodec`，同时持有当前字段定义和模板历史 `fieldBindings`。
2. 编辑、失焦、保存、默认批量、连续、标签、打印预览和 PDF 输出均复用这套解析规则，不再由输出层自行做字符串替换。
3. 字段 ID 仍存在且记录确实返回该字段时显示记录值；字段 ID 仍存在但记录没有该值时显示 `[字段不可读取：当前字段名]`，不得静默显示空白。
4. 字段 ID 已不在当前元数据中时，使用历史标签显示 `[字段已失效：历史字段名]`；持久模板仍保留原 ID，以便字段权限恢复或诊断，绝不迁移到同名新字段。
5. 字段改名只更新编辑标签和当前名称，不修改稳定 ID。旧名称模板只在唯一可解析时迁移；同名、位置或证据不足时阻止保存/加载，不猜测。
6. 任何用户可见表面和输出变量都不得泄露 `@__duowei_field_*`。

# 取舍

- 显式错误文字会占用纸面，但比空白或错绑更可诊断，也不会伪造业务数据。
- 失效 ID 不从模板中自动删除；用户可以在编辑模式主动移除或重新绑定。
- 本决策不改变正常空值语义。只有字段键缺失才判定不可读；SDK 已返回的空值继续按原字段格式显示。
