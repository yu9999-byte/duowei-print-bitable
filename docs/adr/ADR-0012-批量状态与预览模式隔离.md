<title>ADR-0012 — 批量状态与预览模式隔离</title>

- 状态：partially superseded by ADR-0017（批次候选原子提交与草稿守卫仍有效；“批量只读、必须退出后编辑”已取代）
- 日期：2026-09-28
- 范围：Goal v5 / 默认模式批量打印

# 背景

> 历史决策记录：Goal v9 已把批量工作台调整为“左侧批次目录持续存在、右侧预览/编辑切换”。本文件第 2 条及“只能先退出批量再编辑”不再是现行验收要求，现行口径见 ADR-0017。

竞品“排版打印”的批量流程在确认记录后直接进入批次预览，用户看到的是所选记录组成的输出结果，而不是继续停留在模板编辑画布。正式环境已有一张截图显示“已选 3 条”后仍看到“模板编辑”和 `PO-0001` 画布值；该截图尚不能证明候选渲染已完成，但它暴露了批量状态与工作台模式可能不同步的风险。

# 决策

批量候选完整读取、渲染和变量恢复成功后，`WorkspaceShell` 必须原子切换到 `batch-ready + preview`：

1. 批量预览显示同一模板生成的全部记录页面，每条记录保持稳定顺序和文档边界。
2. 批量预览态不展示编辑入口、编辑操作区或可编辑设计器画布；模板编辑只能在退出批量后进行。
3. 用户在编辑态发起批量选择时，先沿用 `SPEC-UX-05` 处理未保存草稿；未完成决策不得启动新的批次上下文。
4. 取消、空选、读取失败和渲染失败继续保留原单条/批次工作区，不因强制预览而破坏可恢复性。

# 取舍

- 保留当前默认模式和 `vue-print-designer@1.7.39`，不复制竞品的连续/标签排版，也不制作第二套画布。
- 批量预览期间暂不支持直接改模板，减少“批次页面已经生成但编辑又改变模板”的状态冲突；用户退出批量后编辑模板。
- 如果正式 E2E 证明当前代码已经在候选完成后进入预览，则只补回归测试和可观测状态，不做无证据的 UI 重构。

# 编辑态续验决策（2026-09-28）

正式 Base 在 `PO-0001` 新建未保存的“新模板 2”后，点击选择记录会先要求决策，符合守卫要求。但点“继续编辑”错误提示宿主记录已切换；点“放弃修改”会重载已保存模板却仍停留在编辑态，飞书选择器取消后打印按钮禁用且主预览为空。选择器取消没有再丢数据，缺口在决策与工作台模式的编排。

保留明确决策先于选择器的既有顺序。用户主动放弃草稿不可逆；此时先回到已保存模板的可打印单条预览，再打开选择器，取消仅保留这个决策后的工作区。用户选择保存并继续时，也先刷新可用的单条预览，确保取消选择器后仍可打印已保存内容。用户选择继续编辑时按请求来源给出真实提示，不把主动批量请求写成宿主切换。这个决定不放宽“未决策不得读取批量记录”和批次提交原子性；如将来要求“放弃后取消仍恢复草稿”，须另设计可逆草稿事务而非悄悄恢复用户已放弃的编辑。
