<title>ADR-0025 — 模板级批量与关联字段语义</title>

# 状态

Accepted，2026-10-11。已随小组件 `1.0.49` / 应用版本 `1.0.46` 仅向灰度企业 `F225904757` 发布并完成正式验收；权限变更“暂无”。

# 背景

正式体验反馈暴露四个不一致：默认与连续在屏幕上看似相同；模板 A 的批量记录会被带到模板 B；自动生成模板擅自加入系统“打印日期”；父记录等单值引用被错误生成为明细表。它们来自四层合同不清，而不是单一 CSS 缺陷。

# 决策

1. 批量会话必须记录发起模板 ID。预览中切换到其他模板时，退出原模板批量并原子加载目标模板的宿主当前记录；目标模板要批量打印必须重新选数。
2. 默认与连续继续共用真实 `vue-print-designer@1.7.39` 输出链。默认用多个固定纸张容器，连续用一个长纸容器；只增加 `@media screen` 的纸张间距和阴影，不改变打印/PDF样式。
3. 自动生成模板只自动放当前表字段。系统“打印日期”仍存在于数据源目录和运行时变量中，供用户手动添加；既有模板不迁移、不删除。
4. 关联字段由网关统一分类：`reference` 为可读文本，空值“—”；`detail` 才读取目标表列并生成原生 table。正式 SDK 证明不能只相信 `property.multiple`：`FieldType.SingleLink` 且目标表等于当前表的单向自关联始终按 `reference`；其他关联再按 `multiple=true` 判定明细。该规则基于字段类型与目标表，不依赖“父记录”等字段名称。

# 结果

- `BatchPrintSession.templateId` 成为批量归属事实，不持久化记录。
- `NormalizedField.linkKind` 成为下游唯一关联展示语义；兼容缺少该字段的既有 detail 结构。
- 屏幕视觉与打印物理页盒职责分离。
- 自动模板更克制，系统字段仍可用且既有模板无损。

# 拒绝方案

- 不把批量记录视为跨模板的全局选择，因为会让用户误以为所有模板共享同一批次。
- 不通过字段名称“父记录/明细”猜语义，也不只依赖 `multiple`；使用字段类型、目标表和基数元数据共同判断。
- 不删除系统打印日期能力，也不批量迁移旧模板。
- 不在 App 外另做预览或画布。
