# 真实环境发现

在测试 Base 的 `PO-0001` 打开“多维打印”后，插件已经进入真实 `vue-print-designer`，但活动模板读取报“活动模板存储版本无效”。原加载流程在此处终止，因此数据源刷新和真实值绑定没有执行。

# Red

向 `tests/template-repository.test.ts` 增加不可读旧模板用例，要求原存储零写入、返回自动模板回退信号并禁用保存。首次运行因缺少 `loadTemplateForUse` 导出失败，证明原实现没有恢复路径。

# Green

1. 新增 `loadTemplateForUse`，有效模板保持原行为；读取异常转为带原错误原因的只读回退结果。
2. `App.vue` 在回退时仍调用 `bindPrintJob(null, job)`，使自动模板、当前字段/系统数据源和当前记录值继续加载。
3. 回退会话将“保存模板”禁用，并提示原模板未覆盖；预览、打印、PDF 仍按真实引擎能力开放。
4. 仓库严格 `load/save` 契约保持不变，不把损坏、未来版本或旧格式静默迁移为新数据。

# 验证

- 目标测试 Red：缺少 `loadTemplateForUse` 导出。
- Green：`tests/template-repository.test.ts` 7/7；全量 `npm test` 50/50。
- `npm run build`：通过，仅有既有包体积警告。
- `npm run upload`：CLI 返回 `Upload succeed`；后台确认对应最新待更新小组件为 `1.0.3`。
- 应用版本 `1.0.3` 已完成灰度发布，灰度企业沿用 `F225904757`；无需再次发版即可继续验收。
- 真实 `PO-0001` 页面显示“活动模板存储版本无效；原模板未覆盖，已改用自动模板并绑定真实数据”，`保存模板` 禁用，预览、打印、导出 PDF 保持可用。
- 页面同时显示“已加载当前记录和动态数据源”，证明不可读模板不会再阻断真实字段绑定；数据源目录逐项截图仍待恢复浏览器调试连接后补齐。

# 下一步

恢复浏览器调试连接后补齐“数据源”下 11 个字段和系统“打印日期”的逐项核验；随后在有效模板场景验证可编辑保存，不得把只读回退会话误判为保存通过。
