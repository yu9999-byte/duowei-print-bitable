# 1. 用户目标

用户在“多维打印”中选择当前数据表的多条记录，确认本次打印批次后，使用同一个模板看到完整批次预览，并通过一次浏览器打印流程打印全部记录；也可以导出一个包含全部所选记录的 PDF。用户必须能知道选中了多少条、选择是否生效、输出顺序是什么，取消选择不能破坏当前单条预览或未保存模板草稿。

# 2. 竞品与平台调研

公开资料确认“排版打印”把“选择数据记录即可一键输出”“根据所选人员快速批量输出”“批量打印、导出”作为实际场景；其核心价值不是循环点击每条记录，而是先确定一组数据，再生成一个批次产物。

2026-09-26 又读取了排版打印官方知识库《批量模式：批量预览/打印多条记录数据》的正文、两段无声操作录屏和示例截图。以下结论已经由官方说明或录屏直接验证，不再属于推测：

1. **详情插件入口**：用户在模板预览顶部点击“进入批量模式”，插件打开自己的“选择记录”弹窗。弹窗列出记录字段、支持勾选和“取消选择”，明确显示“已选中 N / 50”，点击“确定”后才进入批量模式。
2. **右侧边栏入口**：用户直接在左侧多维表格勾选多行；插件感知到已勾选记录后显示“你已经勾选 N 条记录，是否进入批量模式？”，用户再次点击“进入批量模式”确认。录屏未显示插件自制第二套选择表格。
3. 两种入口进入批量后都显示“已选 N 条”，提供“退出”；详情插件还提供“选择记录”以重新选择。批量状态与普通单条状态有清晰区分。
4. 批量预览不是只有“每条一页”。竞品提供三种模式：
   - **默认模式**：按模板原尺寸一条接一条纵向展示，适用于一份文件一张纸；
   - **连续模式**：在连续纸张上纵向拼接多条内容；
   - **标签模式**：在自定义最终纸张尺寸内横向排列并自动换行，适用于一张纸多个标签。
5. 标签模式提供“设置”，显示当前模板尺寸和最终打印尺寸；官方说明默认会按当前模板尺寸的 3 倍扩展最终打印尺寸，用户仍可自定义。
6. 录屏中点击右上角“打印”后打开的是系统浏览器打印预览，而不是逐条弹出多个打印框；一次批次打印可能因为最终纸张尺寸或方向形成多页。
7. 官方说明明确最多选择 **50 条记录**，因此本项目首版 50 条上限从“经验建议”升级为有竞品事实支撑的产品基线；仍需通过本项目真实 Base 性能测试决定最终是否维持该上限。

录屏仍未证明的事项：详情插件点击“取消”后是否完整保留原工作区；选择器返回顺序/表格勾选顺序如何决定输出顺序；浏览器打印与屏内预览是否严格同源；导出 PDF 的具体交互。因此这些仍按本项目的可恢复状态和可验证输出规格设计，不能标记为竞品事实。

# 3. 改造前实现审计（历史基线）

## 3.1 已存在的底层能力

1. `src/host/feishu-context.ts` 已调用官方 `selectRecordIdList`，并对空值去重。
2. `PrintJobBuilder` 按选择器返回顺序冻结记录，拒绝缺失记录、重复读取结果和空选择，不会由异步读取顺序改变打印顺序。
3. `BitableGateway` 可以一次读取多条记录并生成同一 `PrintJob.documents`。
4. `DesignerAdapter` 已支持：
   - 多条记录逐条绑定同一模板；
   - 每条记录生成独立打印页面；
   - 合并后只调用一次 `window.print()`；
   - 调用 `getBatchPdfBlob` 生成批次预览；
   - 调用 `exportBatchPdf` 导出一个 PDF；
   - 多字段 Token 按每条记录分别解析，并在输出后恢复可编辑模板。
5. 自动化已覆盖顺序、去重、完整性、一次打印、一个批量 PDF 和多字段批量值，但尚无正式 Base E2E。

## 3.2 当前用户流程缺口

1. 顶部“批量选择”只是一个孤立按钮，没有形成“选择记录→确认批次→预览→打印”的明显流程。
2. 打开选择器前，`loadRecords(true)` 就清空当前 `printJob`、模板目录和预览；用户取消或空选会丢失原本可用的单条工作区。这违反可恢复交互要求。
3. 选择完成后只显示“已加载 N 条记录”，用户看不到所选记录摘要，无法核对是否选对数据；只能再次打开选择器整体重选。
4. 批量加载后主预览区域没有自动生成批次预览，仍显示面向单条的空态文案；用户必须再点击“刷新预览”，随后批量 PDF 又以遮罩层打开，批次状态不连续。
5. 顶部按钮仍写“打印”“导出 PDF”，没有表达此次操作会输出 N 条记录。
6. 批量预览使用 `getBatchPdfBlob`，浏览器打印使用逐条 `getPreviewHtml` 后合并 HTML；两条路径不是同一渲染结果，不能严格保证“预览是什么，打印就是什么”。这会放大已记录的 BUG-0002 页数一致性风险。
7. 没有记录数量上限、读取/渲染进度和大批次失败边界；浏览器内存或引擎上限尚无正式测量证据。

# 4. 推荐的最小 MVP 用户流程

## 4.1 单条进入

用户从某条记录打开“多维打印”，默认仍看到当前记录和当前模板预览。顶部提供主操作“选择打印记录”，而不是把批量能力作为不明确的附加按钮。

## 4.2 选择批次

1. 点击“选择打印记录”，调用飞书官方记录选择器。
2. 打开选择器前保留当前工作区；取消或空选时单条/批次预览和模板保持不变，只提示“未更改打印记录”。若编辑草稿尚未决策，不能提前丢弃；若用户明确放弃，取消选数只保留已恢复的单条预览，不复活已放弃草稿。
3. 确认选择后再原子替换为批次上下文。
4. 批次栏显示“已选 N 条”，并展示最多前 5 条主字段摘要；更多记录用“等 N 条”表示。提供“重新选择”和“返回当前记录”。MVP 不自制第二套表格选择器，也不要求在插件内逐条拖动排序。

## 4.3 批次预览与输出

1. 选择完成后自动生成批次预览，不要求用户再猜测点击“刷新预览”。
2. 每条记录使用同一活动模板并从新的文档边界开始，按官方选择器返回顺序输出且恰好一次。
3. 主操作改为“打印 N 条”，次操作为“导出 N 条 PDF”。
4. 浏览器打印只弹出一次系统打印对话框；PDF 只生成一个文件。
5. 批次预览和浏览器打印复用同一份已渲染页面集合；不得继续由 PDF Blob 预览和 HTML 打印分别生成两套页面。PDF 导出仍可调用引擎批量 API，但必须与同一记录顺序、字段值和页边界对照验收。

## 4.4 排版模式的 MVP 收敛

竞品已经证明默认、连续、标签三种模式分别解决不同打印任务，但本项目首个批量纵切不应一次复制全部高级排版能力：

1. **Goal v5 首切只实现默认模式**：一条记录形成一个模板文档边界，完整预览整个批次并一次调用浏览器打印；先把选数、状态恢复、真实字段和输出一致性闭环做对。
2. **连续模式、标签模式列为紧随其后的独立切片**：必须先调查 `vue-print-designer@1.7.39` 是否能复用模板原尺寸、计算连续纸张高度、横向排布及自动换行，不得在引擎外重做一套假画布。
3. 默认模式的界面应预留模式切换区，但未实现的模式不得显示为可点击功能。首切可以只显示“默认排版”，或在文案中说明其他排版后续开放。
4. BUG-0002 的预览/打印页数一致性是默认模式验收门；若一条模板在屏内是一页，浏览器打印必须遵循同一页边界，不能把竞品三模式作为绕过分页问题的理由。

# 5. 推荐架构

新增明确的 `BatchPrintSession`/工作台状态，而不是继续用 `documents.length > 1` 隐式猜测模式：

```text
single-ready
  └─ 打开官方选择器（原状态保留）
       ├─ 取消/空选 → single-ready，不改变原状态
       └─ 确认 IDs → batch-loading → batch-ready / batch-error

batch-ready
  ├─ 重新选择 → 保留现批次直到新选择成功
  ├─ 返回当前记录 → single-loading → single-ready
  ├─ 预览 → 使用 canonical rendered pages
  ├─ 打印 N 条 → 同一 canonical rendered pages，一次 window.print
  └─ 导出 N 条 PDF → 同序一个 PDF
```

- `ContextAdapter`：只负责宿主当前记录与官方选择器结果。
- `BatchPrintSession`：保存已确认 record IDs、摘要、顺序、状态和错误；不保存业务值到模板。
- `PrintJobBuilder`：继续作为批次记录与顺序的事实源。
- `DesignerAdapter.renderPrintJobPages`：一次生成批次 canonical pages，供主预览和浏览器打印共同使用。
- `App.vue`：编排会话状态、摘要和操作按钮，不复制字段读取或引擎渲染逻辑。

# 7. MVP 边界与待确认项

- 首版上限为 50 条：与竞品官方说明一致，并作为本项目集中配置的产品基线；仍须通过正式容器大批次测量，若本项目达不到应以性能证据调整，不能静默截断或散落魔法数字。
- Goal v5 首切只承诺默认模式；连续模式和标签模式已经进入产品路线，但必须在真实引擎能力核验和单独 SDD/TDD 切片后实现。
- MVP 不支持跨表选择、不同记录使用不同模板、插件内拖动排序、静默打印、后台生成文件或将 PDF 自动回写附件字段。
- MVP 继续使用真实 `vue-print-designer@1.7.39` 和浏览器原生打印，不自制画布或独立批量 Demo。
- BUG-0002 的单页残片问题仍独立开放；但批次预览与打印必须先统一渲染来源，不能把已知不一致扩散到新批量流程。

# 8. 停止条件

若官方选择器在记录视图宿主中无法稳定返回所选顺序，先以真实响应证据更新 SPEC，不猜测排序；若锁定引擎无法让预览与打印复用同一页面集合，则停止实现并报告引擎限制、可维护性和产品折中，不用循环打开多个打印框冒充批量成功。正式 Base 未取得一次打印框、三条正确内容和一个 PDF 前，本阶段不得标记完成。
