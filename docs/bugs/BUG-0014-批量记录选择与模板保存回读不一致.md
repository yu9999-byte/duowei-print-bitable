# BUG-0014 — 批量记录选择与模板保存回读不一致

- 状态：已修复并通过正式灰度独立测试 Base 核心验收；原业务模板个案待单独复现
- 日期：2026-10-15
- 范围：多维打印记录视图；自动化任务保持暂停

## 用户现象

用户从单条记录选择多条打印记录后能看到完整批量预览，但预览没有保存结果；在批量编辑中保存模板，切换到另一模板再切回，原模板只显示单条，用户感到所选记录和编辑内容都消失。用户明确要求：所选记录按模板永久保存，关闭插件并重开仍可恢复。

## 正式灰度版证据

应用 `1.0.61` / 记录视图 `1.0.57` 的独立测试 Base 中，选择 `O-EMPTY-001`、`O-SINGLE-001`、`O-MULTI-001` 后能看到三页；切换到其他模板再切回只显示宿主单条。批量第二页修改标题并点击保存后，三页预览都显示修改；切换模板再切回，标题仍能在单条页读到。此前单条标题及字号保存回读也成功。因此本次已证实的持久化缺口是**记录选择未写入共享模板配置**；单条视角和“自动化同步失败”的红色提示共同造成“模板内容也没保存”的观感。若用户原业务模板另有内容丢失，需要发布后按该模板继续复现，不用独立测试 Base 的结果替代。

## 根因与修复

旧 `BatchPrintSession` 只在插件内存中保存所选 ID；切换模板调用 `shouldExitBatchOnTemplateSwitch` 后回到宿主单条。模板仓库只持久化画布和排版，预览没有记录选择持久化反馈。

修复候选把有序记录 ID 作为 `StoredTemplate.savedBatchRecordIds` 元数据保存在 Base/table 范围的模板集合中，不放进 `vue-print-designer` 画布，不保存字段值。选择器确认后，只有真实记录读取、完整渲染与飞书存储写入全部成功才提交新预览；切换模板或重开插件时按目标模板的 ID 重新读取实时数据。退出批量会清除当前模板所存 ID；失败保留原预览并给出重试。现有模板编辑 `upsert` 保留记录 ID 元数据。

## 验收门

1. 独立测试 Base 中，模板 A 选择三条、编辑第二页标题、保存；切换 B、切回 A，仍为三条且三页标题一致。
2. 刷新或重开插件后，A 恢复三条且字段值从 Base 实时读取；B 保持自己的选择或单条状态。
3. 重新选择改变顺序与数量，退出批量清除所选；存储失败和不可读记录均不伪报保存成功。
4. `npm test`、生产构建通过；发布后以正式灰度应用和独立测试 Base UI 验收，原业务 Base 只读。

## 2026-10-15 正式灰度验收

应用 `1.0.62`（详情 ID `7696743975482854592`）绑定记录视图 `1.0.58`，状态“灰度中”，已灰度企业仅 `F225904757`，权限变更“暂无”。独立测试 Base 的“自动模板 2”选择 `O-EMPTY-001`、`O-SINGLE-001`、`O-MULTI-001` 后显示“记录已保存”与三页真实值。切至另一模板为单条，切回后恢复三条；进入编辑模式可滚动查看三条。在第二页将共享标题实际改为“批量永久保存验收”并保存，三页标题同步；再次切换和刷新重开插件后，三条、新标题及真实关联明细均回读。保存时未再出现自动化同步失败提示。误建的空白测试子记录已清理，测试表恢复原有六条主记录；原业务 Base 未修改。

本轮没有对用户原业务模板逐个编辑复现，也没有注入存储失败、记录失效或权限拒绝；这些不计为已通过。
