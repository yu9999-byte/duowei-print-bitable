<title>BUG-0008：系统打印日期时区偏差</title>

# 状态

已关闭。已定位并完成 SDD/TDD 修复（151/151，生产构建通过），仅向 `F225904757` 灰度；单条、默认批量、标签、连续四条输出准备路径的跨日自动化回归均通过。`1.0.34/1.0.31` 的正式跨日单条、默认批量、标签批量、连续批量预览/PDF 均已通过；当前 `1.0.37/1.0.34` 未改变该日期逻辑。

# 现象与证据

2026-10-04 正式小组件 `1.0.28` / 应用 `1.0.25`，当地时间 `02:05 +08:00`，连续模板三条/十条、恢复后的默认单条显示系统“打印日期：2026-10-03”。十条实际 PDF 也包含该错误日期。订单下单日期和要求送达日期仍为真实表值，不是本问题的修改对象。

- 正式截图：`artifacts/release-2026-10-04/continuous-ten-result.jpg`、`restored-single-final.jpg`。
- 实际 PDF：`artifacts/release-2026-10-04/pdf-actual/continuous-ten.pdf`，240,143 bytes，一张长纸，SHA256 `6005A75945D7032AB6B6F5CBF7E9502C9653157CB2AE967D4982D61F24F41BB2`。

# 根因

网关以 `new Date().toISOString()` 保存正确生成时刻；`getDocumentVariables` 用 `job.generatedAt.slice(0, 10)` 截取 UTC 日历日期。在正时区凌晨或负时区夜间，本地日期与 UTC 日期不同，因此错一天。该共享数据源函数影响单条及三种批量排版，不能只修连续模板。

# 修复范围与验收

遵循 SPEC-SRC-02 和 ADR-0005：保留原任务时刻，用标准 Date 本地年/月/日生成系统日期，所有记录复用同一时刻；保留系统 ID、旧别名和同名表字段；无效时刻拒绝。先新增 UT-SRC-08 复现跨日失败，再最小修改运行时转换，跑全量测试与生产构建。

2026-10-04 验证：定向测试 Red 12/17（5 项失败）→Green 17/17；六项 UT-SRC-08 覆盖东/西时区跨日、UTC、夏令时/跨年、同批次一致性/业务同名字段和无效时刻。全量 `npm test` 150/150；`npm run build` 通过，仅三项既有 Webpack 包体积/性能警告。候选入口 `assets/main.fbf084bb.js`；正式仍为 `assets/main.9d1ef147.js`。不改系统时区、模板 schema 或业务日期，不新增抽象。过程见 PHASE-04 第 45 节。

正式部署后仍须在本地/UTC 日期不同的时间点核对编辑画布、单条与三种批量预览/PDF。未部署不能声称正式修复；不更改权限、模板或 Base 业务数据，不由 PDF 正确推定系统打印物理页数正确。
