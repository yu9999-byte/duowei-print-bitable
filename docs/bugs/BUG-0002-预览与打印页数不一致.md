# 现象

在真实飞书多维表格记录视图插件“多维打印”中，记录 `PO-0006` 的设计器画布显示一个 A4 页面。点击“打印”后，Microsoft Edge 已能正常打开浏览器原生打印预览，不再出现 `ERR_BLOCKED_BY_CLIENT`；但浏览器打印预览显示两张纸：第一页包含完整订单内容，第二页基本为空，仅在顶部出现一条浅灰色残片。

这说明打印链路已经打通，但预览、打印页数和页面边界尚未一致。第二页不是第二条记录，也不是模板中真实存在的第二个业务页面。

# 证据

- 用户截图 1：设计器中 `PO-0006` 只显示一个页面。
- 用户截图 2：Edge 原生打印预览显示两张纸，第二页只有顶部浅灰色横条。
- 本轮只记录用户提供的真实截图和源码分析；尚未采集生成后的完整 HTML、浏览器打印指标或实体纸张结果。

# 初步原因

当前单条预览与浏览器打印处在不同的样式上下文：

1. 设计器画布/内部预览由 `vue-print-designer` 的 Shadow DOM 承载。
2. 为绕过 Edge 对 `blob:` 打印的拦截，插件调用 `getPreviewHtml()`，把返回 HTML 插入飞书插件当前文档后执行 `window.print()`。
3. 引擎返回页面使用固定画布高度（当前 A4 为 `1123px`），并可能保留设计器预览所需的阴影、溢出或像素取整结果。
4. 页面本身已占满一张纸时，少量视觉溢出或尺寸取整可能被 Edge 分片到第二张纸。截图中第二页顶部的浅灰横条与这种溢出表现一致。

上述是有源码和截图支持的首要假设，但在采集真实打印 DOM 与计算样式前，不把单一 CSS 属性写成最终根因。

# 产品口径

纸张尺寸、方向、边距和缩放一致时，产品的打印预览、浏览器打印预览和最终输出必须保持内容、页序和页数一致。浏览器或用户主动改变纸型、缩放、页边距、页眉页脚，以及物理打印机不可打印区域造成的差异，需单独标明，不能用来掩盖应用自身的分页偏差。

该口径已由 `FR-OUT-01/02/03`、`SPEC-OUT-01/02` 和 `E2E-OUT-01` 覆盖，本问题不是新增范围。

# 建议修复方案（未执行）

1. 建立统一的输出 HTML 规范化步骤，清除设计器专用阴影、外边距、选择态和非打印溢出。
2. 从模板纸张设置生成明确的 `@page` 尺寸、方向和边距规则。
3. 让产品预览与 `window.print()` 复用同一份规范化页面，而不是依赖两个不同的样式容器。
4. 以模板页面节点作为分页单位，最后一页不得产生额外分页或视觉溢出。
5. 不 fork、不替换 `vue-print-designer`，不退回独立 Demo。

# 成本评估

- 仅修复当前 A4 空白第二页：低难度，约 `0.5–1` 个开发日，但不能系统覆盖其他纸型和批量场景。
- MVP 级“预览即打印”（A4 单条＋批量，Edge＋Chrome）：中等难度，约 `2–3` 个开发日，推荐在恢复本问题时采用。
- 完整覆盖 A4/A5/B5/Letter、横纵向、边距、缩放和 PDF 一致性：中高难度，约 `4–7` 个开发日。

# 恢复条件与验收标准

用户当前决定先记录、暂不修改。恢复开发时先按 TDD 新增失败用例和真实 E2E 证据，再改实现。至少满足：

- `PO-0006` 模板预览一页时，Edge 和 Chrome 原生打印预览均为一页且无空白残片页。
- 两页模板严格输出两页，不丢页、不增加第三页。
- 至少三条批量记录各自从新页开始，总页数与统一预览一致。
- 顶部与设计器内部打印入口结果一致。
- PDF 的内容和页序与预览一致；浏览器打印的可控纸张条件被记录。
