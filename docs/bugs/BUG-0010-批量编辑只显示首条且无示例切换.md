<title>BUG-0010 — 批量编辑未展示全部已选记录</title>

- 状态：closed；Goal v13 已正式灰度并完成三模式验收
- 严重级别：P0
- 影响：默认、连续、标签三种批量编辑
- 关联：ADR-0019（错误修复已被取代）、ADR-0020、SPEC-BATCH-09

# 现象

批量预览能展示全部已选记录，但正式 Goal v12 编辑态只显示一条“示例记录”，需要上一条/下一条切换。用户不能像预览一样连续滚动查看全部记录，也不能在任意可见实例上直接修改公共模板。

# 根因

Goal v12 把“一批记录共用一份模板”错误实现为“设计器只绑定一条运行数据，再切换索引”。这解决了首条数据固定问题，却没有满足“完整批次在编辑态同样可见、可滚动、可编辑”的产品要求。它不是引擎滚动高度问题，也不是记录级模板需求。

# 正确行为

进入批量编辑后，真实 `vue-print-designer` 一次展示全部记录：默认模式为全部页面，连续模式为完整长画布，标签模式为完整网格。编辑任意一个实例都更新同一份公共模板并同步到全部实例；各实例仍展示各自真实字段值。保存只保存公共模板，不保存业务数据或投影副本。

# 修复与证据

- 新增 `BatchEditProjection`，实现三种布局的全量投影、公共模板回收、冲突拒绝和投影元数据剥离。
- `DesignerAdapter` 支持每个投影元素的记录值和提交后全量同步。
- `WorkspaceShell` 删除示例索引、上一条/下一条，已有模板和批量新建模板均进入同一全量编辑入口。
- 真实设计器首次验收又发现第三实例文本失焦时只更新当前实例；已将批量 Shadow DOM `focusout` 接入公共模板同步，并在初始绑定时归一化引擎推断变量。对应 Red→Green 回归加入 `tests/designer-adapter.test.ts`。
- 自动化 199/199、生产构建 `assets/main.10b67076.js` 和 `git diff --check` 通过；默认 3/10 条、连续 3 条、标签 3 条、第三实例同步、保存重开单模板及 700px 纵横边界已在真实设计器通过。小组件 `1.0.42` / 应用 `1.0.39` 仅灰度到 `F225904757` 后，正式 Base 再次通过三模式全量展示、末端滚动、真实值和公共模板同步。
