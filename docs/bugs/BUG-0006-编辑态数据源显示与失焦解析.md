<title>BUG-0006 — 编辑态暴露内部 Token 且失焦不解析</title>

- 状态：已关闭（原始 Token 暴露与失焦不解析缺陷已通过正式核心闭环）
- 日期：2026-09-26
- 关联：SPEC-SRC-06/07、FR-DES-08、ADR-0010、PHASE-02G、BUG-0004

# 现象

在正式 Base 的“多维打印”编辑模式中，从左侧复制字段数据源并粘贴到文本组件后，画布直接显示 `@__duowei_field_fld47snZ5u` 一类内部字符串。文本组件结束编辑或失焦后，字符串仍未替换为当前记录的实际字段值。

用户预期是：编辑内容时看到 `@订单编号`、`@备注` 等可理解字段标签；结束编辑后看到 `PO-0001`、`待出库，等待物流上门` 等当前记录值。再次进入编辑时恢复字段标签。模板内部仍需用稳定字段 ID 绑定，不能用显示名称或当前记录值替代。

# 标识含义

`@__duowei_field_fld47snZ5u` 由三部分组成：`@` 表示数据源引用，`__duowei_field_` 是多维打印字段命名空间，`fld47snZ5u` 是飞书字段稳定 ID。该 ID 用于字段改名后保持绑定，但只属于模板持久层，不应直接展示给用户。

2026-09-26 回查原始截图和正式 Base 元数据后确认：截图中的该 Token 位于“备注”文本组件内；当前 `仓库订单表` 中 `fld47snZ5u` 对应“备注”，`fld1PG2I15` 才对应“订单编号”。因此现有证据不支持“订单编号被错误绑定为备注”；已确认的缺陷仍是内部稳定 ID 暴露给用户、失焦未解析真实值。若后续出现标签与稳定 ID 不一致，须作为独立的数据源目录错配缺陷复现，不能从这张截图推断。

# 根因

1. `buildDataSourceClipboardPayload` 生成的 plain text 就是内部稳定 Token；生产路径 `copyDataSource` 只调用 `writeClipboardText(payload.text)`，没有把字段标签和稳定 ID 作为可恢复的结构化数据交给编辑器。
2. 当前没有接管真实设计器的粘贴、内容编辑完成、失焦和再次编辑生命周期。`vue-print-designer` 因此把内部 Token 当作普通文本保存和绘制。
3. `resolveDataSourceTokens` 已能解析字符串，但 `withResolvedOutputTemplate` 只在预览、打印和 PDF 输出前临时调用；编辑画布失焦不经过该流程。
4. Goal v2 自动化测试证明了纯函数解析和输出前临时模板，却没有覆盖真实设计器中的“复制→粘贴→失焦→再次编辑”交互。正式环境截图补出了该测试缺口。

# 产品规则

| 层次 | 表示 | 约束 |
|-|-|-|
| 模板持久层 | 稳定字段/系统 ID | 字段改名后仍绑定；不得保存当前记录值 |
| 内容编辑层 | `@当前字段名` / `@打印日期` | 用户可读；内部 ID 不可见；多个标签与静态文字可组合 |
| 失焦与输出层 | 当前记录实际值 | 切换记录后重新解析；预览、打印、PDF 一致 |

字段被删除、无权读取或旧名称存在歧义时，必须显示明确的“字段已失效/不可读取”状态并阻止误绑，不能回退显示内部 Token。

# 修复边界

1. 保留真实 `vue-print-designer@1.7.39`，不自制替代画布。
2. 三层转换只放在 DataSourceTokenCodec 与 DesignerAdapter；不得向 `App.vue` 堆叠散落的 shadow DOM 查询或字符串补丁。
3. 先核验公开 API、事件和 shadow DOM 编辑契约。公开 API 不足时，只允许在单一版本固定适配层内处理，并以契约测试锁定选择、粘贴、失焦和模板往返。
4. 兼容 Goal v2 已保存的 `@__duowei_field_<ID>` 模板；不得要求用户重建模板，也不得把稳定 ID 批量改成字段名。
5. BUG-0002 页数偏差、BUG-0005 整体视觉风格继续独立处理，不混入本次修复。

# 验收

- 复制“订单编号”并粘贴后，内容编辑态显示 `@订单编号`，不显示内部 Token。
- 结束编辑后显示当前记录订单编号；再次编辑恢复 `@订单编号`。
- 同一组件可组合两个字段、系统项、静态文字和分隔符，第二个字段不覆盖第一个字段。
- 保存重开、字段改名和记录切换后仍按稳定字段 ID 正确解析。
- 字段删除、无权或歧义有明确失效状态，不误绑其他字段。
- 打印预览、浏览器打印和 PDF 与失焦画布显示一致；模板存储中不包含当前记录业务值。

# 正式核心闭环复验（2026-10-06）

在当前灰度小组件 `1.0.35` / 应用 `1.0.32` 的正式 Base 中，使用既有测试模板“新模板 2”和真实记录 `PO-0001/PO-0002` 完成以下连续动作；没有修改 Base 业务记录、权限或灰度范围：

1. `PO-0001` 进入编辑模式，已有文本组件双击后显示友好内容“单价：`@单价`”，没有暴露内部 Token。
2. 将该组件改为“客户数量：`@客户名称 @数量`”；失焦后画布显示“客户数量：北京恒信商贸有限公司 50”。
3. 保存时回显“模板已保存（未写入当前记录值）”；返回预览、切到默认模板再重开“新模板 2”，仍显示 `PO-0001` 的真实值。
4. 再次进入编辑并双击同一组件，内容恢复为“客户数量：`@客户名称 @数量`”，证明稳定绑定可逆且未把当前记录值固化进模板。
5. 切换到 `PO-0002` 后，同一组件自动显示“客户数量：上海锐科电子科技有限公司 100”，同页其他字段也全部切换为 `PO-0002`，证明保存的是字段绑定而非 `PO-0001` 文本。
6. 顶部打印入口只点击一次并进入浏览器原生阻塞流程；自动化通道不能读取系统打印对话框和物理页数，因此不把该动作写成物理打印通过，也不关闭 BUG-0002。
7. 顶部“导出 PDF”生成实际文件 33,789 bytes、PDF 1.4、1 页 A4（`595.502×842.258 pt`），SHA256 `46AB617888CAB02D39C6644E708944C98924BA6870ACCEE11DD78ED1D9AC31BD`。Poppler 渲染确认“客户数量：上海锐科电子科技有限公司 100”及 `PO-0002` 其他真实字段位于同一页，无空白页、明显裁切或内部 Token。证据归档于 `artifacts/release-2026-10-06/pdf-actual/`。

据此，原始缺陷“编辑态暴露内部 Token、失焦不解析，以及多字段保存后固化当前记录值”的正式核心路径已通过，BUG-0006 关闭。字段真实改名后的重开绑定、字段删除/无权/歧义的明确失效状态继续作为 SPEC-SRC-04/06/07 的边界验收项；浏览器原生打印物理页数由 BUG-0002 追踪，不再混入本缺陷状态。
