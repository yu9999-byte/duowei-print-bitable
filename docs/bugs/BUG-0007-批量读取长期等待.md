<title>BUG-0007：批量读取长期等待</title>

# 状态

当前线上为小组件 `1.0.36` / 应用 `1.0.33`，正式资源为 `assets/main.869b0aaa.js`，仅灰度企业 `F225904757`。三种批量正常路径和默认模式恢复链已通过；真实 SDK 超时异常路径与原挂起点仍待现场证据，BUG 保持开放

# 现象

在正式 Base 的独立验收标签中，真实选择 `PO-0001/PO-0002/PO-0003` 后，插件长时间停在“读取中”，超过 45 秒没有进入批量预览。单次重试没有得到稳定结果；当前验收标签随后回到表格单元格编辑态，无法用同一标签可靠重开详情。

# 影响

若任一飞书 SDK 读取 Promise 永不结束，批量工作流会一直忙碌，用户看不到明确失败，也不能判断原批次是否仍可用。

# 根因假设与边界

代码此前直接等待 SDK Promise，没有超时或取消出口。SDK 本身是否因宿主可见性、网络或权限而未 settle，需灰度日志/复测进一步确认；本条不把宿主 Canvas 入口失败当作 SDK 根因定论。

# 修复候选

- 网关为主表、字段、记录、关联表、关联视图和关联字段读取增加单次 15 秒有界超时。
- 超时抛出 `BitableReadTimeoutError`，上层现有候选事务捕获后保留已提交批次、旧预览和旧变量，并显示可重试错误。
- 允许测试注入更短 `timeoutMs`，用 TDD 验证永不 settle 的记录/字段读取不会永久 pending。
