<title>BUG-0011 — 编辑画布底部被裁切</title>

- 状态：已修复并完成正式灰度 E2E
- 发现日期：2026-10-08
- 影响：单条与批量编辑

# 现象

打印预览可以滚动查看整张纸，进入真实设计器后只能看到纸张上部，无法滚动到整张纸的底部和部分边界。

# 根因

工作台 `.canvas-stage` 与 `.designer-host` 使用裁切边界，但 `print-designer` 只有 `min-height: 100%`，没有贯通父级的确定高度。锁定版设计器自带 `.canvas-scroll { height: 100%; overflow: auto }`，因宿主高度链不完整而失去有效滚动空间。

# 修复契约

补齐工作台到 Web Component 的 `height/min-height` 链，让设计器内部滚动区继续作为唯一编辑画布滚动所有者；不得通过第二层外部滚动或自制画布规避。

# 关闭条件

`SPEC-UX-12` 静态契约、932×540/700px 本地真实设计器与正式灰度滚动验收均通过后关闭。上述条件现已满足。

# 本地修复证据

- `.canvas-stage → .designer-host → print-designer` 已建立 `height: 100%` 与 `min-height: 0` 的完整高度链，外层继续 `overflow: hidden`，没有新增第二个纵向滚动容器。
- 真实 `vue-print-designer@1.7.39` 在普通宿主与 700×540 测试壳中均可由设计器内部滚动区到达纸张底边和右边界；两页模板可滚动查看第二页底部。
- `CT-UX-12` 静态契约和全量 195/195 已通过；修复已作为小组件 `1.0.41` / 应用 `1.0.38` 仅灰度至 `F225904757`。
- 正式默认批量编辑的设计器内部滚动区实测 `clientHeight=300`、`scrollHeight=1187`，纵向达到最大 `scrollTop=887`；横向达到 `scrollLeft=52 / maxX=58`。纸张底部与右边界可达，外层未新增第二个滚动容器，关闭本缺陷。
