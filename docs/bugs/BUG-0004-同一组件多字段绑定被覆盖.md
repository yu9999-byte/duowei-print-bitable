<title>BUG-0004 — 同一组件无法追加多个字段</title>

- 状态：已关闭（正式双字段编辑、保存、跨记录与 PDF 通过）
- 日期：2026-09-25
- 关联：SPEC-SRC-03/05/06/07、SPEC-DES-01/02、ADR-0009/0010、PHASE-02F/02G、BUG-0006

# 现象

当前编辑模式允许从左侧“数据源”向画布添加字段。第一个字段可以生成文本元素；再放入第二个字段时，用户看到的是第一个字段被替换，或新字段覆盖在原字段上，无法自然地组成“客户：字段 A，订单号：字段 B”这类同一组件内容。竞品的交互边界是组件可拖动，数据源只复制后粘贴到组件内容中。

# 根因定位

当前外层字段拖拽在 `src/App.vue:601-608` 写入 `application/json`，载荷由 `src/core/data-sources.ts:27-49` 生成：普通字段是 `{ type: "text", payload: { content, variable } }`。锁定的 `vue-print-designer@1.7.39` 对带 `payload` 的拖放走 `handleDrop -> addElement`，语义是新增元素，不是追加到当前元素；当多个元素落在同一位置时，后添加的元素会覆盖视觉区域。

引擎的变量型拖放则会寻找目标文本组件并更新其单一 `variable`。它内部的文本替换逻辑只适合替换/追加一个变量 token，不能把外层当前字段拖拽直接表达成稳定的“同一组件多字段编辑”用例。当前 `DesignerElement` 适配层也只有 `getTemplateData/loadTemplateData` 等公开能力，没有“向选中元素追加 token”的公开 API。

因此，本 Goal 采用竞品的确定交互：组件从左侧“组件”区域拖入画布；数据源从左侧“数据源”区域复制 token（例如 `@__duowei_field_x`），再粘贴到已选中文本组件的内容编辑上下文。数据源行不再注册拖拽事件，也不再负责创建画布元素。多个 token 可以共存，最终仍需保证 token 使用稳定字段 ID、预览和打印都能解析。

# 方案边界

1. 保持真实 `vue-print-designer`，不自制画布、不用 Demo 替代引擎。
2. 组件拖拽只负责创建空组件；数据源复制/粘贴只负责向文本组件内容插入 token，两个动作不共享“拖数据源创建组件”的语义。
3. 先补 Red：同一文本组件内容同时包含两个字段 token 和静态分隔符，重开模板后仍保留顺序，运行时能分别替换为真实值；组件拖入画布仍保持新增元素语义。
4. 优先评估公开 API 可实现的“复制字段 token → 在设计器文本内容输入中粘贴”路径；若需读取选中元素或改写模板快照，必须固定引擎版本、限定适配范围并补契约测试。
5. 本 MVP 的多字段组合对象是文本组件；数组/关联数据继续使用表格组件的专用配置，不把数组强行序列化为普通文本 token。

# 验收

- 一个文本组件可显示至少两个字段和静态分隔符。
- 数据源条目不可拖动；组件条目可以拖动并创建独立组件。
- 第二个字段不会删除或覆盖第一个字段。
- 保存、重开、切换记录后两个字段仍按稳定字段 ID 绑定。
- 预览、浏览器打印和 PDF 输出值一致；关联表格仍使用表格组件，不与文本 token 语义混用。
