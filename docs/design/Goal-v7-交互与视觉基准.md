# 1. 设计目标

多维打印应像飞书多维表格中的原生生产力工具：打开即可确认结果，编辑时专注排版，批量时专注记录与输出。界面不使用营销式品牌区，也不把历史工程恢复动作长期暴露给普通用户。

# 2. 三模式动作矩阵

| 模式 | 左侧 | 中/右主区 | 顶部主要动作 | 明确隐藏 |
|-|-|-|-|-|
| 单条预览 | 模板目录、唯一新建入口 | 当前模板纸张预览 | 选取多条、PDF、打印；工作区内编辑模板 | 数据源、组件、保存、设计器画布 |
| 单条编辑 | 数据源 / 组件 | 真实设计器画布与属性 | 返回预览、唯一保存 | 模板目录、新建/管理、打印、PDF |
| 批量预览 | 批次摘要、前 5 条记录 | 默认/连续/标签只读预览 | 重新选择、退出批量、导出 N 条 PDF、打印 N 条 | 模板目录、编辑、数据源、组件、设计器 |

# 3. 当前入口的处理

| 当前表现 | Goal v7 处理 |
|-|-|
| “重新读取”与“刷新预览”同时显示 | 普通态全部移除；失败对象附近按需显示“重试” |
| 每个模板行常驻“重命名/设默认/删除” | 合并到悬停、聚焦或当前项可见的“更多”菜单 |
| 默认/连续/标签三个新建按钮并列 | 收敛为一个“新建模板”，再选择模板类型 |
| 品牌大标题 + 模板标题 + 预览标题三重层级 | 顶部只保留 16px 产品名和轻量上下文；工作区只保留当前模板标题 |
| 编辑态仍暴露打印/PDF | 隐藏，避免未保存草稿被当成可输出版本 |
| 永久成功状态行 | 只保留短暂反馈；错误、读取中和恢复动作就近显示 |
| 外层页面和纸张 iframe 同时滚动 | 预览工作台拥有唯一纵向滚动；iframe 高度匹配内容 |

# 4. 视觉 Token

- 字体：系统字体；正文/按钮 14/20px，辅助 12/18px，区域标题 16/24px 600。
- 主色：`#3370FF`；正文 `#1F2329`；次级文字 `#646A73`；边框 `#DEE0E3`；工作台 `#F2F3F5`。
- 控件：标准高度 32px、圆角 6px；列表行 48–56px；应用栏 48–52px。
- 间距：4/8/12/16/20/24；一屏最多一个明显主按钮。
- 纸张：白色、轻微单向阴影、水平居中、顶部约 24px；不使用卡片式大圆角。

# 5. 视觉方案的明确差异

本轮只提供两个以内的方案，均遵守同一产品合同：

- 方案 A「目录清晰」：保留 228px 固定左栏，模板与批次信息稳定可扫；适合模板频繁切换。
- 方案 B「画布优先」：预览左栏更窄并强调选中模板与纸张；适合高频确认/输出，但仍不隐藏必要模板入口。

两案都必须展示 5 个真实中文模板、字段/系统数据源、组件拖拽语义以及 932×540 的预览/编辑/批量状态，不得把视觉稿冒充新的独立产品或 Demo。

## 5.1 用户确认（2026-10-07）

用户选择方案 B“画布优先”，并指出 A/B 视觉稿差异过小。实现不得把“画布优先”降级为只缩小几十像素侧栏，须形成可观察的产品差异：预览/批量侧栏采用紧凑目录，非选中项减少次要元信息；纸张获得更多横向空间；700px 窄容器进一步收纳次要上下文但保持模板切换、新建和输出可达。编辑态仍保留足够宽度的数据源/组件操作区，不为扩大画布牺牲字段可读性。

# 6. 批准门

视觉方向已确认为方案 B“画布优先”，并已完成本地产品候选。`CT-UX-08/09/10` 与设计器 Chrome 契约均按 Red→Green 执行；932×540 验证预览/编辑/批量及双模板，700×540 与 1200×700 验证收纳和画布占比。正式灰度仍须单独授权，不能以本地通过替代 E2E-UX-02。
