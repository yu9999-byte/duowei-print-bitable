# 批量保存：检查结论与实施方案

日期：2026-10-14。状态：交互草案待确认，尚未修改产品代码。

## 用户已确认的结果

保存排版和本次记录选择，重新打开后一起恢复。

## 当前行为与原因

用当前 App、真实 vue-print-designer 和隔离的 Feishu SDK 模拟环境检查了完整流程。选中 3 条记录后可以批量预览；批量预览没有保存入口。进入批量编辑后，“保存模板”能保存共享排版，当前 3 条记录也能继续预览。切换到连续排版后，排版模式同样能保存。

刷新后，界面回到宿主当前单条记录。重新选择 3 条记录，已保存的连续排版又能恢复。这说明排版保存可用，缺少的是记录选择的持久化与打开时的恢复流程。

相关路径：

- `src/components/workspace-presentation.ts`：批量预览不显示保存，批量编辑显示保存。
- `src/App.vue`：选择结果只提交到内存中的 batchSession，保存模板不保存记录选择，初始化回到当前记录。
- `src/core/template-repository.ts`：模板会主动移除记录 ID 和运行数据。这一保护应保留，批量配置单独保存。

证据在 `audit.json` 和编号 01–07 的截图中。模拟存储使用 sessionStorage 验证刷新前后的行为；本结论不等同于已在正式飞书环境验收。

## 拟定交互

| 状态 | 保存入口 | 其他行为 |
| --- | --- | --- |
| 单条预览 | 保留现有行为 | 模板目录、选记录、输出、编辑 |
| 单条编辑 | 保存模板 | 隐藏模板目录，保留真实设计器及唯一操作面 |
| 批量预览 | 新增次级“保存批量” | 保存共享排版和记录选择；打印仍是主按钮 |
| 批量编辑 | 原“保存模板”改为“保存批量” | 同一保存路径；成功返回原批量预览 |
| 保存中 | “保存中…”且禁用 | 阻止重复保存及上下文切换 |
| 已保存且没有变更 | “保存批量”禁用 | 模板目录显示“批量 · 3 条” |
| 重开恢复中 | 输出禁用 | 按保存顺序读取最新记录并生成完整预览 |
| 恢复失败 | 显示“重新选择记录”和“重试恢复” | 不显示不完整批次为成功，也不允许输出它 |

选择变化、顺序变化、排版变化和编辑变化都使当前批量重新变为未保存。退出批量仅返回当前记录预览，保留已经保存的配置。

## 保存和恢复的约定

1. 每份模板关联一份批量配置，按多维表格、数据表和模板隔离。保存成功后记住要恢复的模板，重新打开恢复最近一次保存的批量。
2. 模板仍只保存共享排版、字段绑定和排版模式。独立的版本化批量配置保存模板引用与有序记录 ID，不保存字段值、业务数据快照或凭据。
3. 打开时重新读取所选记录的最新数据，保持记录顺序、数量和排版。全部读取、绑定和渲染成功后才提交批量预览；打开不会自动打印。
4. 记录删除、权限不足或临时读取失败时，明确提示并允许重选或重试。不能静默跳过记录生成部分批次。
5. 保存失败保留当前草稿和选择。只有排版、记录选择和恢复指向均保存成功才显示成功；部分写入成功必须说明实际结果，不能笼统声称全部成功或全部回滚。
6. 模板切换遵循模板归属，保存的记录不泄漏到其他模板或数据表。删除模板后，其批量配置不能继续被恢复。
7. 旧模板没有批量配置时保持原单条打开行为；不推断历史记录选择。

## 实施与验收

视觉方向获准后，先补保存／重开恢复／失败／上下文隔离的行为测试，再实现独立批量配置存储和 App 的保存、初始化、模板选择路径。同步修订 SPEC 中“批量仅限临时会话”和“打开固定单条”的旧约定。保留模板清洗规则及真实设计器。

核心验收：选择有序的 3 条记录，编辑共享排版并保存，重新打开恢复同一模板、同一记录顺序和排版；修改源记录后重新打开看到最新数据；默认、连续和标签排版分别验证；取消重选、保存失败、并发更新、恢复失败及切换数据表不得提交半成状态或覆盖其他配置。

运行适当的自动化测试、生产构建和 diff 检查，再用真实设计器捕获 932×540、700px、1200px 界面对照批准稿。当前窄屏纸张水平裁切是继承的预览行为，本次草案不修改纸张尺寸、打印缩放或 PDF 算法。正式飞书环境的重新打开与持久化仍须验收。
