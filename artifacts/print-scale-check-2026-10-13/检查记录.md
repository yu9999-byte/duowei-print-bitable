# 打印内容缩小检查

- 日期：2026-10-13
- 用户现象：导出正常，点击打印后内容看起来缩小；要求打印版面与产品预览一致。
- 当前结论：相同 A4 纸型未测到缩小；已在 A4 内容配 Letter 输出纸型时复现整体缩小至约 94%。本机 Chrome Default 保存的历史纸型确为 Letter，Edge Default 为 A4。用户当次使用的浏览器和纸型尚未确认，因此现场根因仍待定位；未修改生产代码、未发布。

## 检查范围

检查 `src/engine/designer-adapter.ts` 的页面生成、组合、打印样式和 `window.print()` 调用，以及 `src/App.vue` 的预览与打印入口。预览 iframe 和打印入口使用同一组 `RenderedPrintJob.pages`；浏览器打印另加纸张与分页规则。没有发现针对打印内容的额外 `scale()` 或 `zoom`。

另一活动会话当前处理自动化服务。此检查未修改任何生产源码、现有测试、公共项目文档、依赖、发布配置或已有未提交改动；所有新增证据保存在本目录。

## 本地复现方法

使用已有 `tests/browser/workspace-webpack.config.cjs` 开发服务 `127.0.0.1:8081` 和 mock 订单数据；在新建的隔离无界面 Edge/Chrome 浏览器中等待真实引擎生成预览，再点击产品“打印”。测试拦截 `window.print()`，捕获实际打印 DOM；测量打印媒体样式，并将无脚本 DOM 快照通过浏览器生成 PDF，避免应用 `afterprint` 清理影响连续测量。另通过产品“导出 PDF”取得引擎原生输出作视觉对照。

开发服务器存在已有 css-loader warning overlay；仅在隔离测试页记录并移除该覆盖层，未改服务器或项目配置。

复现脚本：`check.cjs`。该脚本需要已有的本地 8081 开发服务，以及当前机器的 Playwright 和浏览器安装。

## 测量结果

| 项目 | 产品预览 | 浏览器打印 |
| --- | --- | --- |
| 页面宽高 | 794 × 1123 px | 794 × 1123 px |
| 标题字号 | 24 px | 24 px，即 PDF 的 18 pt |
| 正文字号 | 14 px | 14 px，即 PDF 的 10.5 pt |
| 正文区域宽度 | 336 px | 336 px |
| 页面 transform | none | none |
| 页面 zoom | 1 | 1 |
| 打印调用次数 | — | 1 |

Edge `154.0.4258.62` 与 Chrome `154.0.8037.99` 结果相同。页面左上坐标在屏内预览含 16 px 的展示留白；扣除页面原点后，标题、文字块的相对位置、宽高和字号均一致。

浏览器 CSS 纸型与指定 A4 纸型都输出 1 页，正文均为 10.5 pt，未出现整体字体缩小。引擎 PDF 为 595.502 × 842.258 pt，浏览器 CSS 纸型为 595.92 × 841.92 pt；纸型换算差异不足 1 pt。两者均以 96 DPI 渲染并查看，标题、分隔线、字段位置、内容大小一致，没有发现缩小、内容遗漏或额外分页。

完整读数：`geometry.json`、`pdf-measurements.json`。视觉证据：`edge-browser-page.png`、`edge-engine-page.png`。

## 未覆盖的关键条件

- 用户实际模板和当次使用的线上版本。
- 正式飞书宿主内调用 `window.print()` 后的原生打印框。
- 原生打印框的纸型、方向、缩放、边距、每张纸的页数，以及目标打印机的可打印区域。
- 实体纸张的实际尺寸。

另测试了 700 × 540 的跨站嵌入工作台；能够生成预览和捕获打印调用，但 Chromium 对该子 frame 的 CDP 会话不提供 `Page.printToPDF`，报 `Page.printToPDF wasn't found`。因此不将独立文档 PDF 测量冒充正式容器原生打印或实体打印证据。

## 后续定位所需

取得用户出问题那次打印框的可见结果与“更多设置”（纸张、缩放、边距），同时确认缩小是在原生打印预览中出现还是实体纸张才出现。再使用该模板和条件对比页面内部比例与文字实际尺寸，区分模板输出、宿主打印或浏览器/打印机缩放的差异。当前证据不能直接认定为用户设置问题，也不足以进行猜测性源码修改。

## 用户补充后的打印配置核查

用户补充“打印的时候才缩小”。未把该表述自行解释为实体纸张已完成打印；仍以“进入打印步骤后发生缩小”记录。

当前应用浏览器接口只有本会话的空白 In-app Browser，没有可读取的用户 Edge/Chrome 页面或系统打印框。因此转为只读检查本机浏览器保存的打印配置和 Windows 默认打印配置。未修改浏览器配置、打印机配置或发出实体打印任务。

- Edge Default：纸型 A4（210 × 297 mm），保存的缩放 100%，默认边距，最近目标为“导出为WPS PDF”。
- Chrome Default：纸型 Letter（215.9 × 279.4 mm），默认边距，最近目标为 HP Universal Printing PCL 6；保存配置中未显式记录缩放值。
- Windows 的 HP Universal Printing PCL 6 和 WPS 虚拟打印机默认纸型均为 A4；Chrome 保存的 Letter 与它们不一致。
- Chrome 保存的 HP A4 能力中可打印区域约为 201.507 × 288.502 mm；这是设备能力，不能用它证明本次浏览器或驱动实际执行了缩放。
- 以上均是保存的配置快照，不代表用户当次使用了 Default Profile、该浏览器或该打印目标。

对同一份真实打印 DOM 快照，以 Chrome 输出 PDF，唯一改变的条件为输出纸型改为 Letter（`preferCSSPageSize: false`，`scale: 1`）；结果如下。

| 条件 | 纸张尺寸 pt | 标题 pt | 正文 pt |
| --- | --- | --- | --- |
| 按内容的 A4 CSS 纸型 | 595.92 × 841.92 | 18.0000 | 10.5000 |
| 按 Letter 输出纸型 | 612 × 792 | 16.9261 | 9.8736 |

即使调用打印 API 的缩放参数为 1，纸型匹配仍使内容实际缩至约 94.03%。这证明“仅在打印时缩小”可以由输出纸型差异导致；它尚不能证明用户现场问题就是这一原因。结果见 `letter-comparison.json`、`chrome-letter-paper.pdf`、`chrome-letter-page.png`。下一步先确认用户使用 Chrome、Edge 还是飞书桌面客户端，并核对该次纸型；若为 A4 模板，应比较选择 A4、100%、每张纸 1 页时的结果。
