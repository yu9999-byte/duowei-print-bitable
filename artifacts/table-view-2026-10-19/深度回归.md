# 双入口功能一致性与详情模式回归

日期：2026-10-19。对象：已灰度应用 1.0.75，详情组件 1.0.68、数据表组件 1.0.3。沿用现有企业 F225904757，本轮未修改产品代码、上传或发布新版本。

结论：当前账号、同一数据表及已覆盖流程中，两入口功能和共享模板回读一致，未发现原详情能力回退。此结论不代表所有权限、数据类型及跨表组合均已穷举。

## 方法

- 在真实正式 iframe 中通过按钮、原生记录选择器和编辑器交互验证；没有注入模拟 SDK、替换模板仓库或直接修改应用内部状态。
- 空白草稿的文本组件使用组件目录真实 dragstart/drop 处理器添加；属性输入触发真实 input 处理器。数据源复制两边均成功；实际键盘粘贴仅视图入口验证，详情入口的文本输入使用属性面板 input，不能据此声称两边键盘粘贴均通过。
- 原始六个模板只读；保存、布局切换及批次操作使用临时模板 `3a1e0860-6550-4c2f-84c0-aa0e6abe1b1a`（空白模板 7），完成后经 UI 删除。
- 对部署源码对应的隔离目录重跑 npm test，376/376 通过，无失败或跳过。输出、迁移与前轮模板管理证据另见 [线上验收](线上验收.md)。
- 浏览器测试时，对自建的两个宿主页开启过 CDP 焦点模拟，以处理后台页可见性暂停；截图均在前台取得。此结果不能证明浏览器任意后台休眠行为。结束时关闭焦点模拟和自建标签页。

连续与标签会为排版副本生成随机 UUID，因此不能将其原始 HTML 哈希描述为相等。归一化只处理 `data-element-id` 属性，没有移除位置、尺寸、样式、真实内容或顺序。
